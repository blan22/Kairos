# kairos Orca 플러그인

Orca 상태 표시줄에 제안 건수를 그리고, 오른쪽 사이드바 패널에 남은 일의 개요, 먼저 볼 일 하나, 묶음 목록을 보여 준다. 에이전트에게 맡길 수 있는 일은 `에이전트 제안` 묶음에 모은다. `세션 열고 시작`을 누르면 `kairos accept`가 worktree를 만들고 세션 창을 앞으로 가져온다. 뒤로 돌아간 뒤에는 이동을 눌러 `kairos move`로 그 세션에 간다.

판단은 kairos에 있다. 플러그인은 그리기와 버튼, 자주 쓰는 조작(포커스, 할 일 추가, 표시 다시 켜기)만 맡는다. 권한은 `trusted-worker`뿐이고 `notifications.show`, `workspace.open`, `mcp.call`은 쓰지 않는다. P0, P1 알림은 kairos가 네이티브 알림 앱 `KairosNotifier`(`ops/notifier`)로만 띄운다. 그래서 `notifications:show`를 더하지 않는다. 알림을 누르면 패널이 그 일을 맨 위에 보여 준다.

## 파일

| 파일 | 역할 |
|---|---|
| `src/config.ts` | 고정 경로(kairos 실행 파일, kairos 홈), 주기, 시간 제한 |
| `src/runner.ts` | execFile 호출, 호출 큐, 버튼 이름에서 argv 만들기 |
| `src/parse.ts` | kairos JSON 계약 v1을 패널 값으로 줄이기 |
| `src/rows.ts` | 목록 묶음과 정렬, 자르기, 접기 기본값, 더 보기 기준, 세션 소식 순서 |
| `src/text.ts` | 표시 문자열, Slack 표기 정리, 허용 호스트 판정, 사용자 문구 |
| `src/status.ts` | 상태 표시줄 값 |
| `src/service.ts` | 폴링, 패널 요청 처리, `reveal.json` 감시 |
| `src/worker.ts` | 워커 진입점 |
| `src/panel.tsx` | 패널 |
| `src/fixtures.ts`, `src/fake-kairos.mjs`, `src/*.test.*`, `src/panel.check.ts` | 시험과 점검 전용. 값은 모두 합성이다 |

## 흐름

- 워커는 시작할 때와 60초마다 `kairos next --json`을 불러 상태 표시줄을 그린다. 이 호출은 예산을 쓰지 않는다. `state.json`은 읽지 않는다. 응답의 `runs.active`가 0보다 크면 그 앞에 `kairos runs --json`으로 세션 상태를 맞춘다. 항목이 먼저 닫혀도 세션을 계속 본다.
- kairos 호출은 큐로 한 번에 하나만 돈다. 앞선 폴링이 안 끝났으면 다음 폴링은 건너뛴다. 호출마다 시간 제한이 있고 넘기면 SIGKILL로 끊는다.
- 패널은 보일 때만 읽는다. 연 순간과 버튼, 새로고침은 `next --seen --surface panel --json`을 쓴다. 폴링이 끝나면 워커가 `kairos.tick`을 보내고 보이는 패널이 `--seen` 없이 다시 그린다. 패널은 Orca가 앞에 있는지 모르므로, 열어 두기만 해서는 노출과 예산에 남지 않는다.
- 패널 버튼은 고정 이름과 항목 ID만 워커로 보낸다. 워커는 ID를 `^[1-9]\d{0,14}$`로 검사하고 `argvFor`로 인자를 새로 만든다. kairos가 준 `argv`는 쓰지 않는다. 예외는 `add`의 제목 하나다. 사용자가 패널에 직접 쓴 값이고 `cleanText`로 200자까지 정리해 `--` 뒤에 둔다.
- 머리말 아래 한 줄은 남은 일의 모양이다. `21건 · 긴급 1 · 밀린 일 3 · 제안 3`처럼 쓰고 0인 값은 뺀다. 밀린 일은 `counts.carriedP1`, 제안은 지금 시작할 수 있는 일이다.
- `포커스`는 25, 50, 90분 중에 고른다. 포커스 중에는 위쪽 띠가 끝나는 시각과 쌓인 일을 말하고 거기서 끝낸다. 긴급 카드가 넘어 와도 띠는 남는다. 상태 표시줄 글자에도 ` · 포커스`가 붙는다.
- `+`는 할 일 입력을 연다. 이어 적을 수 있게 추가 뒤에도 열린 채 비운다. 실패하면 쓴 글을 지우지 않는다. 직접 추가한 일은 P2라서 `여유 있을 때`로 가고 그 묶음은 자주 접혀 있으므로 자취를 그 머리글에 쓴다.
- 줄 높이가 곧 중요도다. 긴급, 세션, 제안, 오늘은 제목을 두 줄 길이(46자)까지 줄바꿈하고 사유 줄을 둔다. 여유 있을 때, 미룬 일, 이전부터 있던 일은 제목과 시각 한 줄이고 사유는 아이콘과 펼친 행에 있다. 아이콘은 사유를 말하며 색이 없다.
- `나중에`의 툴팁과 자취는 `budget.nextBundleAt`으로 돌아올 시각을 쓴다. 시각을 못 읽으면 쓰지 않는다.
- 바닥글은 게이트가 열리고 고장이 없을 때 `수집 지연 없음 · 1분 전 확인`을 쓴다. 지연은 위쪽 경고가 말하므로 그때는 시각만 남는다. 수집 시간 밖은 판정을 안 하므로 정상이라고 쓰지 않고 지연이 없다고만 쓴다.
- 제안을 꺼 두었으면 `다시 켜기`가 `kairos display auto`를 부른다. `kairos pause --resume`은 `--json`이 없어 명령으로 안내한다. `kairos sessions on`은 차단 시험 뒤에 사람이 켜는 안전 장치라 패널에 두지 않는다.
- 세션 소식은 `--seen` 읽기 뒤로 다시 오지 않는다. 패널이 이동하거나 닫을 때까지 들고 있고, 패널을 다시 띄우면 사라진다. 늦게 온 응답의 세션 소식도 버리지 않는다. 틱은 `--seen` 없이 읽어 같은 카드가 또 오므로 닫은 소식은 run과 종류로 기억해 다시 넣지 않는다. 닫기는 kairos를 부르지 않는다. 소식이 떠 있는 동안 그 항목의 목록 줄은 소식과 같은 문구를 쓰고 빠른 이동을 숨긴다. `failed` 소식은 이동 없이 사유를 보여 주고 표시 게이트가 닫혀 있어도 그린다. 목록의 같은 항목이 시작 가능하면 다시 시작을 둔다.
- 끝났거나 확인이 필요한 세션의 항목에는 `되돌리기`가 있다. `kairos accept <id> --cancel`을 부른다.
- 에이전트 제안은 kairos가 고른다. 패널은 `playbook`과 `scope`가 있는 줄을 묶고 `scope`를 그대로 그린다. 접힌 줄에는 버튼이 없고, 펼치면 범위와 `세션 열고 시작`이 있다. 세션은 이 버튼으로만 열린다. 긴급 줄의 제안은 긴급에 남고 접힌 줄에 낱말로 알린다. 카드 안의 접힌 줄도 같다. `actions`에 `start`가 없으면 세션이 잠긴 것이라 버튼 대신 `kairos sessions on`을 보여 준다.
- 목록은 긴급, 세션, 에이전트 제안, 오늘, 여유 있을 때, 미룬 일, 이전부터 있던 일의 묶음이고 묶음 안에서는 최신이 위다. 줄 사이 간격은 묶음 안쪽에만 있어 머리글은 첫 줄에 붙고 묶음 사이가 더 넓다. 한 줄 묶음은 간격이 없다. 세션 소식은 그 위에 있다. 내부 등급 이름은 화면에 쓰지 않는다. 맨 위의 `먼저 볼 일` 카드는 kairos가 고른 한 건이라 이 정렬과 별개다. 지금은 kairos가 가장 오래된 항목을 고른다.
- 세션을 뺀 묶음은 11건 이상이면 최신 8줄만 보이고 `N건 더 보기`로 펼친다. 100건을 넘으면 묶음마다 10줄을 남기고 앞쪽 묶음부터 채운다. 빠진 건수는 머리글 숫자에 더하고 끝줄에 따로 쓴다.
- 행을 누르면 펼쳐지고 행동은 펼친 행에 있다. 한 번에 한 행만 펼친다. 펼친 행이 있으면 틱 결과를 맡아 두었다가 접을 때나 다섯 번째 틱에서 반영한다. 세션 소식은 맡아 두는 동안에도 받는다. 시작이 늦어진 동안에는 맡아 두지 않고, 시작 버튼을 잠갔다가 다음 읽기에서 푼다. 행 펼치기, 묶음 접기, 더 보기, 원문 열기는 kairos를 부르지 않고 노출로 세지 않는다.
- 성공 자취는 묶음 머리글의 오른쪽 칸이나 머리말에 쓴다. 나타나고 사라져도 아래 줄이 움직이지 않는다.
- 조작 실패는 코드를 `actionFailure` 표의 문구로 옮긴다. 표에 없으면 제목만 쓰고 CLI 원문은 보이지 않는다. 누른 자리가 사라진 알림은 위로 띄우고, 닫기를 누르거나 새로고침이 성공하면 지운다.
- `kairos.action`의 응답에는 첫 결과의 `status`와 `warning`이 있다. 시작은 ok여도 같은 이슈의 세션이 이미 있으면 `unchanged`로 오고 시작 버튼이 남으므로, 패널은 사라지지 않는 안내로 알린다.
- 접은 묶음과 더 보기는 `folds` atom에 사용자가 고른 값만 남긴다.
- 알림을 누르면 `KairosNotifier`가 `kairos reveal <id>...`를 부른다. kairos는 홈에 `reveal.json`(`{items, at}`)을 쓰고 패널을 연다. `next --json`은 10분 안의 값을 `reveal`로 싣는다.
- 워커는 kairos 홈 폴더를 `fs.watch`로 본다. 원자 쓰기는 파일을 바꿔 끼우므로 파일이 아니라 폴더를 보고, 이름이 `reveal.json`인 변화만 150ms 잠잠해진 뒤 한 번 `kairos.reveal`로 알린다. 내용은 읽지 않는다. 홈이 없거나 감시가 끊기면 코드만 남기고 다음 폴링에서 다시 건다. 점검 실행과 대부분의 시험은 감시하지 않는다.
- 패널은 `kairos.reveal`을 받으면 `--seen`으로 다시 읽는다. 알림을 누른 것은 사용자가 직접 본 것이기 때문이다. 닫혀 있던 패널은 열릴 때의 읽기가 같은 값을 받는다. `--seen` 읽기가 도는 동안 온 틱은 읽지 않는다. 틱이 그 응답을 버리면 누른 알림이 맡아 둔 틱 뒤로 밀리기 때문이다. 적용은 반영이 끝난 값으로 하므로, 펼친 행이 틱을 맡아 두는 중이면 반영된 뒤에 걸린다. 지금 볼 일이나 목록을 읽지 못한 응답으로는 적용하지 않고 `at`도 남기지 않는다. 다음에 읽은 값이 같은 알림을 건다.
- 적용한 `at`은 `revealAt` atom(`persist: 'plugin'`)에 남겨 같은 알림을 한 번만 건다. 패널을 다시 열어도 다시 걸지 않는다.
- 대상은 세션 소식 아래, `먼저 볼 일` 위의 `알림에서 연 일` 띠로 올린다. 줄은 제 묶음에서 빼 와 두 번 그리지 않는다. 한 건이면 펼친다. 머리글 옆에 누른 시각과 닫기가 있다. 닫기, 띠에서 접기, 띠에서 처리하기, 대상이 모두 사라짐, 새 알림이 띠를 닫거나 바꾼다. 띠에는 목록 줄만 올린다. 지금 카드에 있는 대상은 카드가 보여 주고 띠에 담지 않는다. 그래서 카드에서 처리해 목록으로 내려와도 띠가 뒤늦게 뜨지 않는다. 대상이 모두 없으면 `이미 정리된 일입니다`를 띄운다. 목록이 길어 넘기지 않은 건이 있으면 그 안에 있을 수 있으므로 띄우지 않는다. 게이트가 닫혀 있으면 게이트 사유가 이미 말하므로 따로 알리지 않는다.

상태 표시줄 값

| 상태 | 글자 | 색 |
|---|---|---|
| 게이트 열림 | `kairos 3` | 긴급 danger, 건강 경고 warning, 세션 소식 accent, 그 밖 neutral |
| 포커스 | 끝에 ` · 포커스`, 설명에 끝나는 시각 | 위와 같음 |
| 세션 소식 | 끝에 ` · 세션 1` | 위와 같음 |
| 건강 경고 | 끝에 ` !`, 아이콘 warning | 위와 같음 |
| 게이트 닫힘 | `kairos 기록 중`, `수집 전`, `일시정지`, `표시 꺼짐` | neutral |
| 호출 실패 | `kairos 오류`, 설명에 코드 | danger |

오류 코드: `spawn_failed`, `timeout`, `too_large`, `bad_output`(JSON이 아님. 설치본이 오래되면 이렇게 나온다), `schema`, 그리고 kairos의 `error.code`.

## 보안

- 제목은 패널의 `Text`와 `ListItem title`로만 그린다. `Markdown`, `Link`, `Image`를 쓰지 않는다. Slack 원문 표기는 `displayTitle`이 사람이 읽는 꼴로 바꾼다.
- 주소는 글자로 그리지 않는다. 사용자가 `원문 열기`를 눌렀을 때만 `shell.openExternal`로 연다. 자동으로 열지 않는다. `openableUrl`을 통과한 주소만 버튼을 그린다. 허용 호스트는 `github.com`, `*.slack.com`, `calendar.google.com`, `mail.google.com`, `notion.so`, `*.notion.so`이고 https만 받으며 계정과 포트가 있으면 거절한다. `shell.openExternal`은 권한이 필요 없고 Orca가 사용자에게 확인을 받는다.
- 외부에서 온 제목과 URL은 인자, 셸, 입력창, 세션 프롬프트로 가지 않는다. 워커에는 항목 ID와 고정 버튼 이름만 간다. 사용자가 패널에 직접 쓴 할 일 제목만 `add`의 인자가 되고, 셸을 거치지 않으며 `--` 뒤에 있어 옵션으로 읽히지 않는다. 패널로 가는 값에는 `argv`가 없다.
- `orca.log`에는 오류 코드만 남긴다. `kairos.tick`과 `kairos.reveal`에는 시각만 있다.
- `reveal.json`은 워커가 읽지 않는다. 패널이 받는 `reveal`은 `next --json`을 거친 값이고, ID는 `^[1-9]\d{0,14}$`로 20개까지, 시각은 양수만 받는다. 하나라도 틀리면 통째로 버린다. 알림 앱과 `reveal.json`에는 고정 문구와 ID만 있고 외부 제목과 URL이 없다.
- 경로는 `src/config.ts`의 상수다(`KAIROS_BIN`, `KAIROS_HOME`). 설정이나 패널 입력으로 받지 않는다. `settings:own` 권한을 쓰지 않기 위해서다. `KAIROS_HOME` 환경 변수로 홈을 옮긴 설치에서는 감시가 닿지 않고, 그때는 패널을 열 때의 읽기가 알림을 받는다.

## 시험

```sh
orca plugin validate . --json
orca plugin test . --json
orca plugin check . --json
```

세 명령은 이 기기에서만 돌고 Orca에 올리지 않는다. `orca plugin check`는 버튼을 누를 수 없어 처리 중, 처리 실패, 펼친 행은 `src/panel.test.tsx`로 본다. `orca plugin check`는 워커를 실제로 띄우므로 `ORCA_PLUGIN_CHECK_PANELS`가 있으면 kairos를 부르지 않는다. 시험은 `startWorker`에 가짜 실행기를 넘겨 돌린다.

`orca plugin types`는 Orca 1.4.248에서 `orca-components.d.ts` ENOENT로 실패해 `.orca/types`가 없다. `tsconfig.json`의 extends는 그래서 아직 풀리지 않는다.

## 올리기

코드 권한이 있어 승인이 필요하다. 승인은 사용자가 한다.

`kairos setup`의 마지막 단계가 아래 적재와 승인을 대신한다. Orca가 보여 주는 권한 문구를 띄우고 사용자가 `y`라고 답할 때만 지문으로 승인한다. 손으로 하려면 아래 명령을 부르고, 출력의 `--approve <지문>`을 붙여 한 번 더 부른다. 플러그인 목록에서 켜는 승인(`enable --approve`)으로는 개발 폴더의 승인이 풀리지 않는다.

```sh
orca plugin dev load "$HOME/Library/Application Support/kairos/0.2.0/plugins/orca-panel"
```

`kairos install --apply`가 `plugins` 폴더를 통째로 복사하므로 이 폴더도 설치본에 들어간다. 설치본의 kairos가 단계 2 명령을 가져야 상태 표시줄이 `kairos 오류`에서 벗어난다. 설치 버전이 바뀌면 `KAIROS_BIN`을 고친다. kairos는 실행 파일이라 워커의 Node 버전과 무관하다.

내리기는 `orca plugin dev unload <같은 경로>`다. `kairos uninstall`은 플러그인을 내리지 않고 이 명령만 알려 준다.

첫 적재 때 상태 표시줄 클릭, `Mod+Alt+Shift+K`, 사이드바 아이콘을 각각 눌러 보고 `orca plugin logs`로 `kairos.open` 도달을 확인한다. S7에서 앞의 둘이 워커 명령에 닿지 않았고 원인은 아직 모른다.

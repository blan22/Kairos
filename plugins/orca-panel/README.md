# kairos Orca 플러그인

Orca 상태 표시줄에 제안 건수를 표시하고, 오른쪽 사이드바 패널에 남은 일의 요약, 먼저 볼 일 하나, 그룹별 목록을 보여 준다. 목록은 `지금`, `대기`, `세션`, `상태` 탭으로 나눈다. 에이전트에게 맡길 수 있는 일은 `에이전트 제안` 그룹에 모으고, 펼치면 이유, 권장, 맡길 범위, 시작 순서로 읽힌다. `세션 열고 시작`을 누르면 `kairos accept`가 worktree를 만들고 세션 창을 앞으로 가져온다. 다른 곳으로 이동한 뒤에는 `이동`을 눌러 `kairos move`로 그 세션에 돌아간다.

판단은 kairos가 한다. 플러그인은 화면 그리기와 버튼, 자주 쓰는 조작(포커스, 할 일 추가, 검색, 표시 다시 켜기)만 맡는다. 권한은 `trusted-worker`뿐이고 `notifications.show`, `workspace.open`, `mcp.call`은 쓰지 않는다. P0, P1 알림은 kairos가 네이티브 알림 앱 `KairosNotifier`(`ops/notifier`)로만 띄우므로 `notifications:show` 권한을 추가하지 않는다. 알림을 누르면 패널이 그 일을 맨 위에 보여 준다.

## 파일

| 파일 | 역할 |
|---|---|

| `src/rows.ts` | 목록 그룹과 탭, 정렬, 자르기, 접기 기본값, 더 보기 기준, 세션 소식 순서 |
| `src/text.ts` | 표시 문자열, Slack 표기 정리, 허용 호스트 판정, 사용자 문구, 이유와 권장 문구, 검색어 |

| `src/panel.tsx` | 패널 |
| `src/fixtures.ts`, `src/fake-kairos.mjs`, `src/*.test.*`, `src/panel.check.ts` | 테스트와 점검 전용. 값은 모두 합성이다 |

## 동작

### 폴링과 호출

- 워커는 시작할 때와 60초마다 `kairos next --json`을 호출해 상태 표시줄을 그린다. 이 호출은 예산을 쓰지 않는다. `state.json`은 읽지 않는다.
- 응답의 `runs.active`가 0보다 크면 그 전에 `kairos runs --json`으로 세션 상태를 맞춘다. 항목이 먼저 닫혀도 세션은 계속 추적한다.
- kairos 호출은 큐에 넣어 한 번에 하나만 실행한다. 앞선 폴링이 끝나지 않았으면 다음 폴링은 건너뛴다. 호출마다 시간 제한이 있고, 넘기면 SIGKILL로 종료한다.
- 패널은 보일 때만 읽는다. 패널을 연 순간, 버튼, 새로고침에는 `먼저 볼 일` 카드가 화면에 있으면 `next --seen --surface panel --json`을 쓴다. 카드를 그리지 않는 탭과 검색어로 거르는 화면에서는 `next --seen-ready --surface panel --json`으로 읽는다. 이 읽기는 세션 소식만 확인으로 적고 카드 노출과 예산은 건드리지 않는다. 설치된 kairos가 `--seen-ready`를 모르면(오류 코드 `usage`) 워커는 그 뒤로 기록 없는 `next --json`으로 읽는다. 폴링이 끝나면 워커가 `kairos.tick`을 보내고, 보이는 패널은 `--seen` 없이 다시 그린다. 패널은 Orca가 앞에 있는지 알 수 없으므로, 열어 두기만 해서는 노출과 예산에 기록되지 않는다.
- 패널 버튼은 고정 이름과 항목 ID만 워커로 보낸다. 워커는 ID를 `^[1-9]\d{0,14}$`로 검사하고 `argvFor`로 인자를 새로 만든다. kairos가 준 `argv`는 쓰지 않는다. 예외는 `add`의 제목 하나뿐이다. 사용자가 패널에 직접 입력한 값이고, `cleanText`로 200자까지 정리해 `--` 뒤에 둔다.

### 헤더와 조작

- 헤더 아래 한 줄은 남은 일의 요약이다. `21건 · 긴급 1 · 밀린 일 3 · 제안 3`처럼 쓰고 0인 값은 뺀다. 밀린 일은 `counts.carriedP1`, 제안은 지금 시작할 수 있는 일의 수다.
- `포커스`는 25, 50, 90분 중에서 고른다. 포커스 중에는 상단 배너가 끝나는 시각과 쌓인 일을 보여 주고, 거기서 포커스를 끝낼 수 있다. 긴급 카드가 들어와도 배너는 유지된다. 상태 표시줄 문구에도 ` · 포커스`가 붙는다.
- `+`는 할 일 입력창을 연다. 이어서 입력할 수 있도록 추가한 뒤에도 입력창을 연 채로 비운다. 실패하면 입력한 글을 지우지 않는다. 직접 추가한 일은 P2라서 대기 탭의 `여유 있을 때` 그룹으로 간다. 대기 탭에서는 그룹 제목에 `추가했습니다`를 띄우고, 다른 탭에서는 헤더에 `대기 탭에 추가했습니다`를 띄운다.
- 돋보기는 검색창을 연다. 제목, 사유, 출처, 그룹 이름에서 모든 낱말이 들어 있는 줄을 탭을 가로질러 찾는다. 검색 중에는 탭 자리에 결과를 한 목록으로 그리고 30줄까지만 보여 준다. 검색어가 `먼저 볼 일` 카드의 일과 맞으면 카드도 함께 보여 준다. 검색어 입력은 화면의 줄을 거를 뿐이고 kairos를 호출하지 않는다. 게이트가 닫혀 있으면 검색이 없다.
- `나중에`의 툴팁과 완료 표시에는 `budget.nextBundleAt`으로 다시 올라올 시각을 쓴다. 시각을 읽지 못하면 쓰지 않는다.
- `나중에` 옆의 `⋯`는 다시 볼 때를 고르는 줄을 연다. `1시간 뒤`는 `kairos later <id> --when hour`, `내일 아침`은 `--when tomorrow`(다음 근무일의 근무 시작 시각)를 호출한다. 고르거나, 다시 누르거나, 다른 행을 펼치면 닫힌다. 설치된 kairos가 `--when`을 모르면 업데이트하라고 알린다.
- 푸터는 게이트가 열려 있고 문제가 없을 때 `수집 지연 없음 · 1분 전 확인`을 표시한다. 지연이 있으면 상단 경고가 알려 주므로 푸터에는 시각만 남긴다. 수집 시간 밖에는 판정을 하지 않으므로 '정상'이라고 쓰지 않고 '지연 없음'이라고만 쓴다.
- 제안을 꺼 두었다면 `다시 켜기`가 `kairos display auto`를 호출한다. `kairos pause --resume`은 `--json`이 없어서 명령을 안내만 한다. `kairos sessions on`은 차단 테스트 뒤에 사람이 켜는 안전 장치이므로 패널에 두지 않는다.
- 성공 표시는 그룹 제목의 오른쪽이나 헤더에 띄운다. 나타나고 사라져도 아래 줄이 움직이지 않는다.
- 조작이 실패하면 오류 코드를 `actionFailure` 표의 문구로 바꿔 보여 준다. 표에 없으면 제목만 쓰고 CLI 원문은 보여 주지 않는다. 누른 위치가 사라진 경우의 알림은 위쪽에 띄우고, 닫기를 누르거나 새로고침이 성공하면 지운다.
- `kairos.action`의 응답에는 첫 결과의 `status`와 `warning`이 들어 있다. 시작이 ok여도 같은 이슈의 세션이 이미 있으면 `unchanged`로 오고 시작 버튼이 남는다. 이때 패널은 사라지지 않는 안내로 알린다.

### 탭

| 탭 | 내용 |
|---|---|
| `지금` | `먼저 볼 일` 카드와 긴급, 에이전트 제안, 오늘 그룹 |
| `대기` | 여유 있을 때, 미룬 일, 이전부터 있던 일 그룹 |
| `세션` | 에이전트에게 맡긴 일 |
| `상태` | 소스별 수집 상태, 열린 일의 건수, `먼저 볼 일` 카드의 횟수 예산 |

- 탭 이름 뒤의 숫자는 그 탭의 건수다. 목록이 길어 패널로 넘기지 않은 줄, `알림에서 연 일`로 올라간 줄, `먼저 볼 일` 카드의 일(`지금` 탭)도 센다. 0이면 숫자를 쓰지 않는다. 지연된 소스가 있으면 `상태` 탭 이름에 ` !`를 붙인다. 미연결과 기록 없음은 설정 상태라서 붙이지 않는다.
- 패널을 열면 항상 `지금` 탭이다. 닫았다가 다시 열어도, 알림을 눌러도 검색을 닫고 `지금` 탭으로 돌아온다. 고른 탭은 저장하지 않는다. 손댈 일을 먼저 보여 주기 위해서다.
- `먼저 볼 일` 카드는 `지금` 탭에만 있다. 다른 탭에서 누른 버튼과 새로고침은 `--seen-ready`로 읽는다. 보지 않은 카드가 노출로 기록되어 예산을 쓰지 않게 하기 위해서다. 검색어로 거르는 동안에도 `--seen-ready`로 읽는다. 검색어가 카드와 맞아 카드가 보여도 같다. 답으로 온 카드가 검색어와 맞지 않으면 그리지 않은 카드가 노출로 남기 때문이다.
- 카드가 있을 때 `지금` 탭으로 돌아오거나 검색어로 거르던 검색을 닫으면 `--seen`으로 한 번 읽는다. 카드가 다시 화면에 나왔기 때문이다. 그런 읽기가 이미 돌고 있으면 다시 읽지 않는다. 그 밖의 탭 전환과 검색 입력은 kairos를 호출하지 않는다.
- 노출을 적을지는 요청을 보낼 때의 화면으로 정한다. `지금` 탭에서 새로고침을 누르고 답이 오기 전에 다른 탭으로 옮기면, 그 답의 카드는 `지금` 탭으로 돌아오기 전에 노출로 적힌다.
- 그리는 것은 고른 탭뿐이다. 탭을 바꾸거나 검색으로 가려져서 보이지 않게 된 행은 접는다. 카드의 행도 같다. 보이지 않는 행이 틱 결과를 붙잡아 두지 않게 하기 위해서다.
- `지금` 탭이 비어 있고 다른 탭에 일이 있으면 `대기 N건 보기`, `세션 N건 보기`로 건너가는 버튼을 둔다. 빈 `대기`, `세션` 탭은 무엇이 모이는 곳인지 알려 준다.
- 세션 소식, 알림에서 연 일, 경고는 탭 위에 있어 어느 탭에서든 보인다.
- `상태` 탭에는 조작이 없다. 소스 줄은 `next --json`의 `sources`를 그대로 그린다. 상태 낱말은 `정상`, `N분 지연`, `수집 기록 없음`, `미연결`, `수집 시간 아님`이고 손봐야 할 수 있는 상태(지연, 기록 없음, 미연결)만 강조한다. `sources`가 없는 옛 kairos에서는 건수와 예산만 보여 주고 `kairos doctor`를 안내한다.
- 게이트가 닫혀 있으면 탭을 그리지 않는다. 대신 게이트 사유 아래에 수집 상태를 덧붙여, 기록만 하는 동안에도 수집이 도는지 볼 수 있게 한다.

### 목록

- 목록은 긴급, 에이전트 제안, 오늘(지금 탭), 여유 있을 때, 미룬 일, 이전부터 있던 일(대기 탭), 세션(세션 탭) 그룹으로 나뉘고, 그룹 안에서는 최신이 위다. 세션 소식은 탭 위에 있다. 내부 등급 이름은 화면에 쓰지 않는다.
- 맨 위의 `먼저 볼 일` 카드는 kairos가 고른 한 건이므로 이 정렬과 별개다. 현재 kairos는 가장 오래된 항목을 고른다.
- 줄 사이 간격은 그룹 안쪽에만 둔다. 그래서 그룹 제목은 첫 줄에 붙고 그룹 사이가 더 넓다. 한 줄짜리 그룹에는 간격이 없다.
- 줄 높이가 곧 중요도다. 긴급, 세션, 제안, 오늘은 제목을 두 줄 길이(46자)까지 줄바꿈하고 사유 줄을 둔다. 여유 있을 때, 미룬 일, 이전부터 있던 일은 제목과 시각을 한 줄에 쓰고, 사유는 아이콘과 펼친 행에서 보여 준다. 아이콘은 사유를 나타내며 색을 쓰지 않는다.
- 세션을 제외한 그룹은 11건 이상이면 최신 8줄만 보여 주고 `N건 더 보기`로 펼친다. 100건을 넘으면 그룹마다 10줄을 남기고 앞쪽 그룹부터 채운다. 빠진 건수는 그룹 제목의 숫자에 더하고 마지막 줄에 따로 쓴다.
- 행을 누르면 펼쳐지고, 동작 버튼은 펼친 행에 있다. 한 번에 한 행만 펼친다.
- 펼친 행이 있으면 틱 결과를 보류했다가 행을 접을 때나 다섯 번째 틱에서 반영한다. 세션 소식은 보류 중에도 받는다. 시작이 지연되는 동안에는 보류하지 않고, 시작 버튼을 잠갔다가 다음 읽기에서 푼다.
- 행 펼치기, 그룹 접기, 더 보기, 원문 열기는 kairos를 호출하지 않고 노출로도 세지 않는다.
- 접을 수 있는 그룹은 미룬 일과 이전부터 있던 일이다. 이전부터 있던 일은 접혀 있고, 미룬 일은 여유 있을 때가 6건 이상일 때만 접혀 있다. 여유 있을 때는 대기 탭의 주 내용이라 접지 않는다.
- 접은 그룹과 더 보기 상태는 `folds` atom에 사용자가 고른 값만 저장한다.

### 이유와 권장

- 펼친 행과 단건 카드는 맨 위에 `이유 · …`와 `권장 · …` 두 줄을 쓴다. 왜 올라왔는지와 다음에 할 일이다.
- 문구는 `text.ts`의 고정 표(`guideOf`)에서 사유 코드로 고른다. kairos나 외부에서 온 글은 섞지 않는다. 표에 없는 사유는 두 줄을 그리지 않는다.
- 시작할 수 있는 제안이 붙은 일은 권장 끝에 `에이전트에게 맡길 수도 있습니다.`를 덧붙인다. 그 아래로 맡길 범위, 시작하면 일어나는 일, `세션 열고 시작`이 이어진다.
- 세션이 있는 일은 사유 대신 세션 상태가 권장을 정한다(답을 기다림, 끝남, 창을 찾지 못함 등). 미룬 일은 권장 자리에 다시 올라올 때를 쓴다.
- 단건 카드는 제안이 붙었는지와 밀린 일인지를 `에이전트 제안`, `밀린 일` 배지로 알린다.

### 세션과 에이전트 제안

- 에이전트 제안은 kairos가 고른다. 패널은 `playbook`과 `scope`가 있는 줄을 그룹으로 모으고 `scope`를 그대로 그린다. 접힌 줄에는 버튼이 없고, 펼치면 범위와 `세션 열고 시작`이 나온다. 세션은 이 버튼으로만 열린다.
- 긴급 줄에 붙은 제안은 긴급 그룹에 남기고 접힌 줄에 문구로 알린다. 카드 안의 접힌 줄도 같다.
- `actions`에 `start`가 없으면 세션이 잠긴 것이다. 버튼 대신 `kairos sessions on`을 안내한다.
- 세션 소식은 `--seen`이나 `--seen-ready`로 읽은 뒤에는 다시 오지 않는다. 그래서 패널이 이동하거나 닫을 때까지 직접 보관한다. 패널을 다시 열면 사라진다. 늦게 도착한 응답의 세션 소식도 버리지 않는다.
- 틱은 `--seen` 없이 읽으므로 같은 카드가 다시 온다. 닫은 소식은 run과 종류로 기억해 다시 넣지 않는다. 닫기는 kairos를 호출하지 않는다.
- 소식이 떠 있는 동안 그 항목의 목록 줄은 소식과 같은 문구를 쓰고 빠른 이동 버튼을 숨긴다.
- `failed` 소식은 이동 버튼 없이 사유를 보여 주고, 표시 게이트가 닫혀 있어도 그린다. 목록의 같은 항목이 시작 가능한 상태면 `다시 시작`을 둔다.
- 끝났거나 확인이 필요한 세션의 항목에는 `되돌리기`가 있다. `kairos accept <id> --cancel`을 호출한다.

### 알림에서 열기

- 알림을 누르면 `KairosNotifier`가 `kairos reveal <id>...`를 호출한다. kairos는 홈에 `reveal.json`(`{items, at}`)을 쓰고 패널을 연다. `next --json`은 10분 안의 값을 `reveal`로 싣는다.
- 워커는 kairos 홈 폴더를 `fs.watch`로 감시한다. 원자적 쓰기는 파일을 교체하는 방식이므로 파일이 아니라 폴더를 감시하고, 이름이 `reveal.json`인 변화만 150ms 동안 잠잠해진 뒤 한 번 `kairos.reveal`로 알린다. 내용은 읽지 않는다. 홈이 없거나 감시가 끊기면 오류 코드만 남기고 다음 폴링에서 다시 감시를 건다. 점검 실행과 대부분의 테스트에서는 감시하지 않는다.
- 패널은 `kairos.reveal`을 받으면 검색을 닫고 `지금` 탭으로 돌아온 뒤 `--seen`으로 다시 읽는다. 대상이 카드 안에 있어도 보이게 하기 위해서다. 알림을 눌렀다는 것은 사용자가 직접 봤다는 뜻이기 때문이다. 닫혀 있던 패널은 열릴 때의 읽기에서 같은 값을 받는다.
- `--seen` 읽기가 진행 중일 때 들어온 틱은 읽지 않는다. 틱이 그 응답을 버리게 되면 누른 알림이 보류한 틱 뒤로 밀리기 때문이다.
- 알림 대상은 반영이 끝난 값에 적용한다. 펼친 행이 틱을 보류하고 있다면 반영된 뒤에 적용된다. 지금 볼 일이나 목록을 읽지 못한 응답에는 적용하지 않고 `at`도 기록하지 않는다. 다음에 읽은 값이 같은 알림을 적용한다.
- 적용한 `at`은 `revealAt` atom(`persist: 'plugin'`)에 저장해 같은 알림을 한 번만 적용한다. 패널을 다시 열어도 다시 적용하지 않는다.
- 알림 대상은 세션 소식 아래, `먼저 볼 일` 위의 `알림에서 연 일` 영역에 올린다. 해당 줄은 원래 그룹에서 빼 오므로 두 번 그려지지 않는다. 한 건이면 펼친 상태로 보여 준다. 영역 제목 옆에 누른 시각과 닫기 버튼이 있다.
- 이 영역은 닫기, 영역 안에서 접기, 영역 안에서 처리하기, 대상이 모두 사라짐, 새 알림 중 하나가 일어나면 닫히거나 바뀐다.
- 이 영역에는 목록 줄만 올린다. '지금 볼 일' 카드에 있는 대상은 카드가 보여 주므로 영역에 넣지 않는다. 그래서 카드에서 처리해 목록으로 내려와도 영역이 뒤늦게 나타나지 않는다.
- 대상이 모두 없으면 `이미 정리된 일입니다`를 띄운다. 목록이 길어 패널로 넘기지 않은 건이 있으면 그 안에 있을 수 있으므로 띄우지 않는다. 게이트가 닫혀 있으면 게이트 사유가 이미 설명하므로 따로 알리지 않는다.

## 상태 표시줄

| 상태 | 문구 | 색 |
|---|---|---|
| 게이트 열림 | `kairos 3` | 긴급 danger, 상태 경고 warning, 세션 소식 accent, 그 밖 neutral |
| 긴급 있음 | 건수 뒤에 ` · 긴급 1` | 위와 같음 |
| 포커스 | 끝에 ` · 포커스`, 설명에 끝나는 시각 | 위와 같음 |
| 세션 소식 | 끝에 ` · 세션 1` | 위와 같음 |
| 상태 경고 | 끝에 ` !`, 아이콘 warning | 위와 같음 |
| 게이트 닫힘 | `kairos 기록 중`, `수집 전`, `일시정지`, `표시 꺼짐` | neutral |
| 호출 실패 | `kairos 오류`, 설명에 코드 | danger |

오류 코드: `spawn_failed`, `timeout`, `too_large`, `bad_output`(JSON이 아님. 설치본이 오래되면 이렇게 나온다), `schema`, 그리고 kairos의 `error.code`.

## 보안

- 제목은 패널의 `Text`와 `ListItem title`로만 그린다. `Markdown`, `Link`, `Image`는 쓰지 않는다. Slack 원문 표기는 `displayTitle`이 사람이 읽기 좋은 형태로 바꾼다.
- 주소는 텍스트로 그리지 않는다. 사용자가 `원문 열기`를 눌렀을 때만 `shell.openExternal`로 연다. 자동으로 열지 않는다. `openableUrl`을 통과한 주소에만 버튼을 그린다. 허용 호스트는 `github.com`, `*.slack.com`, `calendar.google.com`, `mail.google.com`, `notion.so`, `*.notion.so`이고, https만 받으며 계정 정보나 포트가 있으면 거절한다. `shell.openExternal`은 권한이 필요 없고 Orca가 사용자에게 확인을 받는다.
- 외부에서 온 제목과 URL은 인자, 셸, 입력창, 세션 프롬프트로 전달하지 않는다. 워커에는 항목 ID와 고정 버튼 이름만 전달한다. 사용자가 패널에 직접 입력한 할 일 제목만 `add`의 인자가 되고, 셸을 거치지 않으며 `--` 뒤에 두므로 옵션으로 해석되지 않는다. 패널로 전달하는 값에는 `argv`가 없다.
- 다시 볼 때 고르기는 고정 버튼 이름(`later_hour`, `later_tomorrow`)만 보낸다. `--when`의 값은 워커가 정한 두 낱말뿐이다.
- 읽기의 기록 범위는 패널이 보내는 참거짓 두 값(`seen`, `ready`)으로만 정한다. 워커는 참인지만 보고 고정된 인자 세 벌 가운데 하나를 고른다. 둘 다 참이면 `seen`을 따른다.
- 검색어는 패널 안에서만 쓴다. 워커와 kairos로 보내지 않고, 정규식이 아니라 글자 포함으로 비교한다.
- `sources`는 소스 이름을 `^[a-z][a-z0-9_]{0,31}$`로, 상태를 정해진 다섯 값으로 검사해 12줄까지 받고 틀린 줄은 버린다. 이름표는 `Text`로만 그리고 상태는 패널의 고정 낱말로 바꿔 그린다.
- `orca.log`에는 오류 코드만 남긴다. `kairos.tick`과 `kairos.reveal`에는 시각만 들어 있다.
- `reveal.json`은 워커가 읽지 않는다. 패널이 받는 `reveal`은 `next --json`을 거친 값이고, ID는 `^[1-9]\d{0,14}$`로 20개까지, 시각은 양수만 받는다. 하나라도 틀리면 통째로 버린다. 알림 앱과 `reveal.json`에는 고정 문구와 ID만 있고 외부 제목과 URL은 없다.
- 경로는 `src/paths.ts`의 상수다(`KAIROS_BIN`, `KAIROS_HOME`). 설정이나 패널 입력으로 받지 않는다. `settings:own` 권한을 쓰지 않기 위해서다. `KAIROS_HOME` 환경 변수로 홈을 옮긴 설치에서는 감시가 동작하지 않고, 이때는 패널을 열 때의 읽기가 알림을 받는다.

## 테스트

```sh
orca plugin validate . --json
orca plugin test . --json
orca plugin check . --json
```

- 세 명령은 로컬에서만 실행되고 Orca에 업로드하지 않는다.
- `orca plugin check`는 버튼을 누를 수 없으므로 처리 중, 처리 실패, 펼친 행, `지금`이 아닌 탭, 검색은 `src/panel.test.tsx`로 확인한다. 스토리북에서는 탭을 눌러 볼 수 있다.
- `orca plugin check`는 워커를 실제로 띄운다. 그래서 `ORCA_PLUGIN_CHECK_PANELS`가 있으면 kairos를 호출하지 않는다.
- 테스트는 `startWorker`에 가짜 실행기를 넘겨서 돌린다.
- `orca plugin types`는 Orca 1.4.248에서 `orca-components.d.ts` ENOENT로 실패해 `.orca/types`가 만들어지지 않는다. 그래서 `tsconfig.json`의 extends는 아직 해석되지 않는다.

## 설치

코드 실행 권한이 있는 플러그인이므로 승인이 필요하다. 승인은 사용자가 한다.

`kairos setup`의 마지막 단계가 아래 로드와 승인을 대신한다. Orca가 보여 주는 권한 문구를 출력하고, 사용자가 `y`라고 답할 때만 지문으로 승인한다. 수동으로 하려면 아래 명령을 실행하고, 출력에 나온 `--approve <지문>`을 붙여 한 번 더 실행한다. 경로의 `0.2.0`은 설치한 버전에 맞춘다. 플러그인 목록에서 켜는 승인(`enable --approve`)으로는 개발 폴더의 승인이 풀리지 않는다.

```sh
orca plugin dev load "$HOME/Library/Application Support/kairos/0.3.0/plugins/orca-panel"
```

- `kairos install --apply`가 `plugins` 폴더를 통째로 복사하므로 이 폴더도 설치본에 들어간다.
- 워커는 `current` 링크를 통해 설치된 kairos를 호출한다. 버전이 바뀌어도 경로 상수를 고칠 필요가 없다. 설치본의 kairos가 오래되어 패널이 호출하는 명령을 지원하지 않으면 상태 표시줄에 `kairos 오류`가 나온다.
- kairos는 네이티브 실행 파일이므로 워커의 Node 버전과 무관하다.
- 언로드는 `orca plugin dev unload <같은 경로>`로 한다. `kairos uninstall`은 플러그인을 언로드하지 않고 이 명령만 알려 준다.

처음 로드할 때 상태 표시줄 클릭, `Mod+Alt+Shift+K`, 사이드바 아이콘을 각각 눌러 보고 `orca plugin logs`로 `kairos.open`에 도달하는지 확인한다. 이전 점검에서는 앞의 두 가지가 워커 명령에 도달하지 않았고, 원인은 아직 확인하지 못했다.

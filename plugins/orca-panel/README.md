# kairos Orca 플러그인

Orca에서 kairos를 쓰는 플러그인입니다. 상태 표시줄에 제안 건수를 띄우고, 오른쪽 사이드바 패널에 남은 일의 요약과 먼저 볼 일 하나, 그룹별 목록을 보여 줍니다. 에이전트에게 맡길 수 있는 일은 패널에서 바로 claude 세션으로 넘길 수 있습니다.

판단은 kairos가 합니다. 플러그인은 화면을 그리고 버튼을 전달하는 일, 그리고 자주 쓰는 조작(포커스, 할 일 추가, 검색, 표시 다시 켜기)만 맡습니다.

- 권한은 `trusted-worker`와 플러그인 자체 저장소(`storage:own`)뿐입니다. `notifications.show`, `workspace.open`, `mcp.call`은 쓰지 않습니다.
- 저장소에는 새 일 표시의 기준(항목 ID와 수)만 둡니다.
- P0, P1 알림은 kairos가 네이티브 알림 앱 `KairosNotifier`(`ops/notifier`)로만 띄웁니다. 그래서 `notifications:show` 권한을 추가하지 않습니다. 알림을 누르면 패널이 그 일을 맨 위에 보여 줍니다.

## 설치

코드를 실행하는 플러그인이라 Orca에서 승인을 받아야 합니다. 보통은 `kairos setup`의 마지막 단계가 로드와 승인을 대신합니다. setup은 Orca가 보여 주는 권한 문구를 그대로 출력하고, `y`라고 답할 때만 지문으로 승인합니다.

> [!IMPORTANT]
> 승인은 사용자가 합니다. 플러그인 목록에서 켜는 승인(`enable --approve`)으로는 개발 폴더의 승인이 풀리지 않습니다.

직접 하려면 아래 명령을 실행하고, 출력에 나온 `--approve <지문>`을 붙여 한 번 더 실행하세요. 경로의 `0.4.2`는 설치한 버전으로 바꿉니다.

```sh
orca plugin dev load "$HOME/Library/Application Support/kairos/0.4.2/plugins/orca-panel"
```

setup은 로드하거나 승인한 뒤 설치본 패널의 `.orca`를 지우고 `orca plugin restart local.kairos`를 실행합니다. 손으로 로드했다면 이 두 단계도 직접 하세요. Orca(1.4.255에서 확인)는 개발 폴더를 승인할 때 `.orca`를 빼고 해시를 적지만, 워커를 띄울 때는 `.orca`까지 넣고 잽니다. components 패널이면 `dev load`가 매번 `.orca/types`를 쓰기 때문에, 그대로 두면 워커가 `content hash mismatch`로 뜨지 않습니다. 개발 트리에서 편집기 타입이 필요하면 `orca plugin types`로 다시 만드세요.

그 밖에 알아 둘 점입니다.

- `kairos install --apply`가 `plugins` 폴더를 통째로 복사하므로 이 폴더도 설치본에 들어갑니다.
- 워커는 `current` 링크를 통해 설치된 kairos를 호출합니다. 버전이 바뀌어도 경로 상수를 고칠 필요가 없습니다. 설치본의 kairos가 오래되어 패널이 호출하는 명령을 지원하지 않으면 상태 표시줄에 `kairos 오류`가 나옵니다.
- kairos는 네이티브 실행 파일이라 워커의 Node 버전과 상관없습니다.
- 언로드는 `orca plugin dev unload <같은 경로>`로 합니다. `kairos uninstall`은 플러그인을 언로드하지 않고 이 명령만 알려 줍니다.

### 처음 로드한 뒤 확인

상태 표시줄 클릭, `Mod+Alt+Shift+K`, 사이드바 아이콘을 하나씩 눌러 보고, `orca plugin logs`로 `kairos.open`에 도달하는지 확인하세요. 이전 점검에서는 앞의 두 가지가 워커 명령에 도달하지 않았고, 원인은 아직 확인하지 못했습니다.

## 화면 구성

패널은 머리말, 프로바이더 칩, 진행 상태 탭, 목록으로 이루어집니다. 세션 소식(세션 상태가 바뀌었을 때 오는 카드), 알림에서 연 일, 경고는 칩과 탭 위에 있어서 어느 탭에서든 보입니다. 패널이 마지막으로 본 뒤 새로 온 일은 칩, 탭, 줄에 빨간 점으로, 상태 표시줄에는 ` ●`로 알립니다.

카드와 알림을 낼지 정하는 [표시 게이트](../../docs/concepts.md)가 닫혀 있으면 탭을 그리지 않습니다. 대신 게이트 사유 아래에 수집 상태를 덧붙여, 기록만 하는 동안에도 수집이 도는지 볼 수 있게 합니다.

### 머리말과 조작

머리말 아래 한 줄은 남은 일의 요약입니다. `21건 · 긴급 1 · 밀린 일 3 · 제안 3`처럼 쓰고 0인 값은 뺍니다. 밀린 일은 `counts.carriedP1`, 제안은 지금 시작할 수 있는 일의 수입니다.

- **포커스**: 25분, 50분, 90분 가운데 고릅니다. 포커스 중에는 상단 배너에 끝나는 시각과 쌓인 일이 나오고, 배너에서 바로 포커스를 끝낼 수 있습니다. 긴급 카드가 들어와도 배너는 남습니다. 상태 표시줄 문구에도 ` · 포커스`가 붙습니다.
- **`+`**: 할 일 입력창을 엽니다. 이어서 입력할 수 있도록, 추가한 뒤에도 입력창을 연 채로 비웁니다. 실패하면 입력한 글을 지우지 않습니다. 직접 추가한 일은 P2라서 대기 탭의 `여유 있을 때` 그룹으로 갑니다. 대기 탭에서는 그룹 제목에 `추가했습니다`가, 다른 탭에서는 머리말에 `대기 탭에 추가했습니다`가 뜹니다.
- **돋보기**: 검색창을 엽니다. 제목, 사유, 출처, 그룹 이름에 모든 낱말이 들어 있는 줄을 탭을 가로질러 찾습니다. 검색 중에는 탭 자리에 결과를 한 목록으로 그리고 30줄까지만 보여 줍니다. 검색어가 `먼저 볼 일` 카드의 일과 맞으면 카드도 함께 보입니다. 검색어 입력은 화면의 줄을 거르기만 하고 kairos를 호출하지 않습니다. 게이트가 닫혀 있으면 검색이 없습니다.
- **`나중에`**: 툴팁과 완료 표시에 다시 올라올 시각(`budget.nextBundleAt`)을 씁니다. 시각을 읽지 못하면 쓰지 않습니다.
- **`⋯`**: `나중에` 옆에 있고, 다시 볼 때를 고르는 줄을 엽니다. `1시간 뒤`는 `kairos later <id> --when hour`를, `내일 아침`은 `--when tomorrow`(다음 근무일의 근무 시작 시각)를 호출합니다. 고르거나, 다시 누르거나, 다른 행을 펼치면 닫힙니다. 설치된 kairos가 `--when`을 모르면 업데이트하라고 알립니다.
- **`다시 켜기`**: 제안을 꺼 두었을 때 나오고 `kairos display auto`를 호출합니다. `kairos pause --resume`은 `--json`이 없어서 명령만 안내합니다. `kairos sessions on`은 차단 테스트 뒤에 사람이 켜는 안전 장치라서 패널에 두지 않습니다.

푸터는 게이트가 열려 있고 문제가 없을 때 `수집 지연 없음 · 1분 전 확인`을 표시합니다. 지연이 있으면 상단 경고가 알려 주므로 푸터에는 시각만 남깁니다. 수집 시간 밖에는 판정하지 않으니 '정상'이라고 쓰지 않고 '지연 없음'이라고만 씁니다.

성공 표시는 그룹 제목의 오른쪽이나 머리말에 띄웁니다. 나타나고 사라져도 아래 줄이 움직이지 않습니다. 조작이 실패하면 오류 코드를 `actionFailure` 표의 문구로 바꿔 보여 줍니다. 표에 없는 코드면 제목만 쓰고 CLI 원문은 보여 주지 않습니다. 누른 위치가 사라졌다는 알림은 위쪽에 띄우고, 닫기를 누르거나 새로고침이 성공하면 지웁니다.

### 프로바이더 칩

탭 위의 칩 줄에서 출처를 고릅니다. 칩은 `전체`와 연결된 소스(`sources`에서 `not_connected`가 아닌 것)를 일이 없어도 늘 같은 순서(GitHub, Slack, Calendar, Gmail, Notion)로 둡니다. 직접 추가한 일(`직접 추가`)과 모르는 소스의 일(`기타`)은 있을 때만 칩이 생깁니다. 칩 이름은 kairos가 준 소스 이름표를 씁니다.

- 칩의 숫자는 그 출처에서 `지금` 탭에 놓일 일의 수입니다.
- 고른 칩은 채운 버튼, 나머지는 글자 버튼입니다. 고를 곳이 하나뿐이면 칩 줄을 그리지 않습니다.
- 칩을 고르면 목록과 탭 건수가 그 출처의 일로 바뀝니다. `먼저 볼 일` 카드는 카드의 일이 모두 그 출처에서 왔을 때만 보입니다.
- 목록이 길어 패널로 넘기지 않은 줄은 출처를 알 수 없어서 `전체`에서만 셉니다.
- 여러 출처의 일이 섞여 보이는 화면(`전체`나 검색)에서는 줄 아이콘이 출처 아이콘이고, 사유 줄의 첫 낱말이 출처입니다. 한 출처만 보일 때는 아이콘이 사유를 나타내고 출처 낱말을 뺍니다.
- 패널을 다시 열거나 알림을 누르면 `전체`의 `지금` 탭으로 돌아옵니다. 고른 칩의 일이 모두 사라지고 연결도 없으면 `전체`로 돌아옵니다.

### 진행 상태 탭

| 탭 | 내용 |
|---|---|
| `지금` | `먼저 볼 일` 카드와 긴급, 에이전트 제안, 오늘 그룹 |
| `대기` | 여유 있을 때, 미룬 일, 이전부터 있던 일 그룹 |
| `세션` | 에이전트에게 맡긴 일 |

- 탭 이름 뒤의 숫자는 고른 출처에서 그 탭에 있는 일의 수입니다. 목록이 길어 패널로 넘기지 않은 줄, `알림에서 연 일`로 올라간 줄, `먼저 볼 일` 카드의 일(`지금` 탭)도 셉니다. 0이면 숫자를 쓰지 않습니다.
- 패널을 열면 항상 `지금` 탭입니다. 닫았다가 다시 열거나 알림을 눌러도 검색과 수집 상태를 닫고 `지금` 탭으로 돌아옵니다. 손댈 일을 먼저 보여 주려고 고른 탭과 칩은 저장하지 않습니다.
- 칩을 고를 때 `지금` 탭에 그 출처의 새 일이 없고 다른 탭에 있으면 그 탭으로 옮깁니다.
- `지금` 탭이 비어 있고 다른 탭에 일이 있으면 `대기 N건 보기`, `세션 N건 보기`로 건너가는 버튼을 둡니다. 비어 있는 `대기`, `세션` 탭은 무엇이 모이는 곳인지 알려 줍니다.

### 수집 상태

머리말의 `수집 상태` 버튼(파형 아이콘)을 누르면 탭 대신 소스별 수집 상태, 열린 일의 건수, `먼저 볼 일` 카드의 횟수 예산을 그립니다. 다시 누르면 닫힙니다. 이 화면에는 조작이 없습니다.

- 소스 줄은 `next --json`의 `sources`를 그대로 그립니다. 상태 낱말은 `정상`, `N분 지연`, `수집 기록 없음`, `미연결`, `수집 시간 아님`이고, 손봐야 할 수 있는 상태(지연, 기록 없음, 미연결)만 강조합니다.
- 지연된 소스가 있으면 버튼이 warning 색이 되고 이름에 `지연된 소스가 있습니다`가 붙습니다. 미연결과 기록 없음은 설정 상태라서 버튼에 표시하지 않습니다.
- `sources`가 없는 옛 kairos에서는 건수와 예산만 보여 주고 `kairos doctor`를 안내합니다.

### 목록

탭마다 다음 그룹으로 나뉘고, 그룹 안에서는 최신이 위입니다. 내부 등급 이름은 화면에 쓰지 않습니다.

- `지금` 탭: 긴급, 에이전트 제안, 오늘
- `대기` 탭: 여유 있을 때, 미룬 일, 이전부터 있던 일
- `세션` 탭: 세션

맨 위의 `먼저 볼 일` 카드는 kairos가 고른 한 건이라 이 정렬과 상관없습니다. 지금 kairos는 가장 오래된 항목을 고릅니다.

줄 높이가 곧 중요도입니다. 긴급, 세션, 제안, 오늘은 제목을 두 줄 길이(46자)까지 줄바꿈하고 사유 줄을 둡니다. 여유 있을 때, 미룬 일, 이전부터 있던 일은 제목과 시각을 한 줄에 쓰고, 사유는 아이콘과 펼친 행에서 보여 줍니다. 아이콘은 출처나 사유를 나타내며 색을 쓰지 않습니다.

- 줄 사이 간격은 그룹 안쪽에만 둡니다. 그래서 그룹 제목은 첫 줄에 붙고 그룹 사이가 더 넓습니다. 한 줄짜리 그룹에는 간격이 없습니다.
- 행을 누르면 펼쳐지고, 동작 버튼은 펼친 행에 있습니다. 한 번에 한 행만 펼칩니다.
- 펼친 줄은 테두리를 바꾸지 않고 바탕만 옅게 칠합니다. 누를 때 줄 높이와 테두리가 바뀌어 아래 줄이 흔들리지 않게 하려는 것입니다.
- 세션을 뺀 그룹은 11건 이상이면 최신 8줄만 보여 주고 `N건 더 보기`로 펼칩니다. 100건을 넘으면 그룹마다 10줄을 남기고 앞쪽 그룹부터 채웁니다. 빠진 건수는 그룹 제목의 숫자에 더하고 마지막 줄에 따로 씁니다.
- 접을 수 있는 그룹은 미룬 일과 이전부터 있던 일입니다. 이전부터 있던 일은 처음부터 접혀 있고, 미룬 일은 여유 있을 때가 6건 이상일 때만 접혀 있습니다. 여유 있을 때는 대기 탭의 주 내용이라 접지 않습니다.
- 접은 그룹과 더 보기 상태는 `folds` atom에 저장합니다. 사용자가 고른 값만 저장합니다.

### 이유와 권장

펼친 행과 단건 카드의 맨 위에는 세 줄이 나옵니다. 왜 올라왔는지(`이유 · …`), 무엇을 보고 그렇게 판단했는지(판단 근거 배지), 다음에 무엇을 하면 되는지(`권장 · …`)입니다.

- 이유는 kairos가 준 `why.rule`(항목을 연 정책 규칙)의 고정 문장을 먼저 씁니다. 예를 들어 `p1.ci_failed`는 `내 PR의 CI 검사가 실패했습니다.`입니다. 규칙이 없거나 표에 없으면 사유 코드의 문구(`guideOf`)를 씁니다.
- 근거 배지는 `why.facts`의 사실 코드(`PR`, `내 담당`, `검사 실패`, `변경 요청됨`, `참석 응답 전` 등)와 kairos가 센 수(`소식 3건`, `참석자 6명`, 회의 시작 시각)입니다. 막는 사실은 danger, 기다리는 사실은 warning, 풀린 사실은 success 색입니다. 표에 없는 코드는 그리지 않습니다.
- 시작할 수 있는 제안이 붙은 일은 권장 끝에 `아래 제안대로 에이전트에게 맡길 수도 있습니다.`를 덧붙입니다.
- 세션이 있는 일은 사유 대신 세션 상태로 권장을 정합니다(답을 기다림, 끝남, 창을 찾지 못함 등). 미룬 일은 권장 자리에 다시 올라올 때를 씁니다.
- 단건 카드는 제안이 붙었는지, 밀린 일인지를 `에이전트 제안`, `밀린 일` 배지로 알립니다.

모든 문구는 `text.ts`의 고정 표에서 고릅니다. kairos나 외부에서 온 글은 섞지 않습니다.

### 에이전트 제안과 세션

에이전트 제안은 kairos가 고릅니다. 패널은 `playbook`과 `scope`가 있는 줄을 `에이전트 제안` 그룹으로 모읍니다. 접힌 줄에는 버튼이 없고, 펼치면 제안 상자와 `세션 열고 시작`이 나옵니다. 세션은 이 버튼으로만 열립니다. 펼친 줄은 이유, 판단 근거, 권장, 맡길 범위, 근거, 일할 곳, 에이전트가 하는 일, 시작 순서로 읽힙니다.

제안 상자의 제목은 플레이북이 하는 일로, `에이전트가 이슈를 고칩니다`, `에이전트가 리뷰 초안을 씁니다`, `에이전트가 답변 초안을 씁니다` 가운데 하나입니다. 그 아래로 다음 내용이 차례로 옵니다.

1. `scope`
2. 맡겨도 된다고 본 근거(`why.offer.checks`): 내게 배정된 이슈, 아직 열려 있음, 작업할 저장소가 정해져 있음, 같은 일의 세션이 없음 등
3. 세션이 일할 곳: 작업 저장소와 기준 브랜치. 이슈가 다른 저장소에 있으면 이슈 저장소도 씁니다.
4. 접어 둔 `에이전트가 하는 일`: 단계, 끝나면 남는 것, 하지 않는 일

`세션 열고 시작`을 누르면 `kairos accept`가 worktree를 만들고 세션 창을 앞으로 가져옵니다. 다른 곳으로 옮긴 뒤에는 `이동`을 눌러 `kairos move`로 그 세션에 돌아갑니다.

- 긴급 줄에 붙은 제안은 긴급 그룹에 남기고, 접힌 줄에 문구로 알립니다. 카드 안의 접힌 줄도 같습니다.
- `actions`에 `start`가 없으면 세션이 잠긴 것입니다. 버튼 대신 `kairos sessions on`을 안내합니다.
- `kairos.action`의 응답에는 첫 결과의 `status`와 `warning`이 들어 있습니다. 시작이 ok여도 같은 이슈의 세션이 이미 있으면 `unchanged`로 오고 시작 버튼이 남습니다. 이때 패널은 사라지지 않는 안내로 알립니다.
- 세션 소식이 떠 있는 동안 그 항목의 목록 줄은 소식과 같은 문구를 쓰고 빠른 이동 버튼을 숨깁니다.
- `failed` 소식은 이동 버튼 없이 사유를 보여 주고, 게이트가 닫혀 있어도 그립니다. 목록의 같은 항목이 시작할 수 있는 상태면 `다시 시작`을 둡니다.
- 끝났거나 확인이 필요한 세션의 항목에는 `되돌리기`가 있습니다. `kairos accept <id> --cancel`을 호출합니다.

### 알림에서 연 일

알림을 누르면 그 일이 세션 소식 아래, `먼저 볼 일` 위의 `알림에서 연 일` 영역에 올라옵니다. 원래 그룹에서 빼 오므로 두 번 그려지지 않습니다. 한 건이면 펼친 상태로 보여 줍니다. 영역 제목 옆에는 누른 시각과 닫기 버튼이 있습니다.

- 닫기, 영역 안에서 접기, 영역 안에서 처리하기, 대상이 모두 사라짐, 새 알림 가운데 하나가 일어나면 영역이 닫히거나 바뀝니다.
- 영역에는 목록 줄만 올립니다. '지금 볼 일' 카드에 있는 대상은 카드가 보여 주므로 넣지 않습니다. 그래서 카드에서 처리해 목록으로 내려와도 영역이 뒤늦게 나타나지 않습니다.
- 대상이 모두 없으면 `이미 정리된 일입니다`를 띄웁니다. 목록이 길어 패널로 넘기지 않은 건이 있으면 그 안에 있을 수 있으므로 띄우지 않습니다. 게이트가 닫혀 있으면 게이트 사유가 이미 설명하므로 따로 알리지 않습니다.

내부 동작은 [알림에서 열기](#알림에서-열기)에 있습니다.

### 새 일 표시

패널이 마지막으로 본 뒤 새로 열린 일은 줄의 사유 줄 앞에 빨간 `● 새 일`, 그 일이 있는 탭 이름 뒤에 ` ●`, 그 출처 칩 옆에 빨간 점으로 표시합니다. 점 자리는 늘 비워 두므로 점이 생기고 사라져도 칩이 밀리지 않습니다.

- 기준은 게이트가 열린 뒤 처음 읽은 목록입니다. 그때 있던 일은 목록이 길어 넘기지 않은 일까지 포함해 새 일로 치지 않고, 그 뒤에 열린 일만 새 일입니다. kairos 기록을 지워 ID가 기준보다 작아지면 기준을 다시 잡습니다.
- 기준선 항목, 직접 추가한 일, 미룬 일, 세션에 맡긴 일은 새 일이 아닙니다.
- 새 일 줄을 그린 지 2초가 지나면 본 것으로 저장합니다. 패널을 닫아도 남고, 상태 표시줄의 점도 그때 꺼집니다.
- 화면의 점은 그 화면(고른 칩, 검색, 수집 상태, 패널 보임)을 떠날 때 지웁니다. 탭 전환은 화면을 바꾸지 않습니다. 보는 동안이나 탭을 오갈 때 점이 사라지면 탭과 칩의 이름이 줄면서 머리말이 흔들리기 때문입니다.

기준을 저장하는 방법은 [새 일 기준 저장](#새-일-기준-저장)에 있습니다.

### 상태 표시줄

| 상태 | 문구 | 색 |
|---|---|---|
| 게이트 열림 | `kairos 3`, 아이콘 gauge | 긴급 danger, 상태 경고 warning, 세션 소식과 새 일 accent, 그 밖 neutral |
| 새 일 | 건수 뒤에 ` ●`, 설명 첫 줄에 `패널에 아직 보지 않은 새 일이 있습니다` | 위와 같음 |
| 긴급 있음 | 건수 뒤에 ` · 긴급 1` | 위와 같음 |
| 포커스 | 끝에 ` · 포커스`, 설명에 끝나는 시각 | 위와 같음 |
| 세션 소식 | 끝에 ` · 세션 1` | 위와 같음 |
| 상태 경고 | 끝에 ` !`, 아이콘 warning | 위와 같음 |
| 게이트 닫힘 | `kairos 기록 중`, `수집 전`, `일시정지`, `표시 꺼짐` | neutral |
| 호출 실패 | `kairos 오류`, 설명에 코드 | danger |

- 새 일 점은 패널이 저장소에 쓴 기준과 `next --json`의 `newest`(가장 큰 열린 항목 ID)로 정합니다. 기준보다 큰 ID가 있거나 아직 보지 않은 새 일이 남아 있으면 찍습니다. 패널이 기준을 고치면 워커는 kairos를 다시 부르지 않고 마지막 값으로 다시 그립니다. 패널을 한 번도 열지 않았거나 저장소를 읽지 못하면 점이 없습니다. 빨강은 긴급의 몫이라 점은 accent 색입니다.
- 상태 표시줄과 사이드바 아이콘은 `gauge`입니다. 알림 앱 아이콘(열린 고리와 점)에 가장 가까운 Orca 아이콘입니다. Orca의 사이드바 아이콘은 정해진 아이콘 이름만 받고 배지를 붙일 수 없어서, 플러그인 목록의 아이콘(`assets/icon.png`)만 알림 앱과 같은 그림을 씁니다.

오류 코드는 `spawn_failed`, `timeout`, `too_large`, `bad_output`, `schema`, 그리고 kairos의 `error.code`입니다. `bad_output`은 출력이 JSON이 아니라는 뜻이고, 설치본이 오래되면 이렇게 나옵니다.

## 동작 상세

패널을 고치는 사람을 위한 내용입니다.

### 폴링과 호출

- 워커는 시작할 때와 60초마다 `kairos next --json`을 호출해 상태 표시줄을 그립니다. 이 호출은 예산을 쓰지 않습니다. `state.json`은 읽지 않습니다.
- 응답의 `runs.active`가 0보다 크면 그 전에 `kairos runs --json`으로 세션 상태를 맞춥니다. 항목이 먼저 닫혀도 세션은 계속 추적합니다.
- kairos 호출은 큐에 넣어 한 번에 하나씩 실행합니다. 앞선 폴링이 끝나지 않았으면 다음 폴링은 건너뜁니다. 호출마다 시간 제한이 있고, 넘기면 SIGKILL로 종료합니다.
- 폴링이 끝나면 워커가 `kairos.tick`을 보내고, 보이는 패널은 `--seen` 없이 다시 그립니다.
- 패널 버튼은 고정 이름과 항목 ID만 워커로 보냅니다. 워커는 ID를 `^[1-9]\d{0,14}$`로 검사하고 `argvFor`로 인자를 새로 만듭니다. kairos가 준 `argv`는 쓰지 않습니다. 예외는 `add`의 제목 하나입니다. 사용자가 패널에 직접 입력한 값이고, `cleanText`로 200자까지 정리해 `--` 뒤에 둡니다.

### 노출 기록

패널은 보일 때만 읽습니다. 기본은 카드가 화면에 있으면 `--seen`, 없으면 `--seen-ready`이고, 아래에 예외가 있습니다.

| 언제 | 읽는 명령 |
|---|---|
| 패널을 연 순간, 버튼, 새로고침에서 `먼저 볼 일` 카드가 화면에 있을 때 | `next --seen --surface panel --json` |
| 같은 때, 카드를 그리지 않는 탭이나 검색어로 거르는 화면일 때 | `next --seen-ready --surface panel --json` |
| 워커 폴링 뒤 `kairos.tick`을 받았을 때 | `--seen` 없이 다시 그림 |

`--seen-ready`는 세션 소식만 확인으로 적고 카드 노출과 예산은 건드리지 않습니다. 설치된 kairos가 `--seen-ready`를 모르면(오류 코드 `usage`) 워커는 그 뒤로 기록 없는 `next --json`으로 읽습니다. 패널은 Orca가 앞에 있는지 알 수 없어서, 패널을 열어 두기만 해서는 노출과 예산에 기록되지 않습니다.

다음 화면은 `--seen-ready`로 읽습니다. 일부는 카드가 보여도 마찬가지입니다. 답으로 올 카드가 그 화면에 그려진다는 보장이 없기 때문입니다.

- 카드는 `지금` 탭에만 있습니다. 다른 탭에서 누른 버튼과 새로고침은 `--seen-ready`로 읽습니다. 보지 않은 카드가 노출로 기록되어 예산을 쓰지 않게 하려는 것입니다.
- 검색어로 거르는 동안에도 `--seen-ready`입니다. 검색어가 카드와 맞아 카드가 보여도 같습니다. 답으로 온 카드가 검색어와 맞지 않으면 그리지 않은 카드가 노출로 남기 때문입니다.
- 칩을 고른 화면도 카드가 보여도 늘 `--seen-ready`입니다. kairos는 출처와 상관없이 답으로 올 카드를 고르므로, 그 화면에 그리지 않을 카드가 노출로 적힐 수 있습니다.

반대로 `--seen`으로 한 번 읽는 때도 있습니다.

- 카드가 있을 때 `지금` 탭으로 돌아오거나, 검색어로 거르던 검색을 닫으면 카드가 다시 화면에 나왔으므로 `--seen`으로 읽습니다. 그런 읽기가 이미 돌고 있으면 다시 읽지 않습니다.
- `전체`로 돌아오면 `--seen`으로 읽습니다.
- 알림을 누르면 `--seen`으로 다시 읽습니다([알림에서 열기](#알림에서-열기)).

그 밖의 탭 전환과 검색 입력은 kairos를 호출하지 않습니다. 행 펼치기, 그룹 접기, 더 보기, 원문 열기도 kairos를 호출하지 않고 노출로 세지 않습니다.

노출을 적을지는 요청을 보낼 때의 화면으로 정합니다. `지금` 탭에서 새로고침을 누르고 답이 오기 전에 다른 탭으로 옮기면, 그 답의 카드는 `지금` 탭으로 돌아오기 전에 노출로 적힙니다.

### 틱 반영과 행 접기

펼친 행이 있으면 틱 결과를 보류했다가, 행을 접을 때나 다섯 번째 틱에서 반영합니다. 세션 소식은 보류 중에도 받습니다. 시작이 지연되는 동안에는 보류하지 않고, 시작 버튼을 잠갔다가 다음 읽기에서 풉니다.

그리는 것은 고른 탭뿐입니다. 탭을 바꾸거나 검색으로 가려져 보이지 않게 된 행은 접습니다. 카드의 행도 같습니다. 보이지 않는 행이 틱 결과를 붙잡아 두지 않게 하려는 것입니다.

### 세션 소식 보관

세션 소식은 `--seen`이나 `--seen-ready`로 읽은 뒤에는 다시 오지 않습니다. 그래서 이동하거나 닫을 때까지 패널이 직접 보관합니다. 패널을 다시 열면 사라집니다. 늦게 도착한 응답의 세션 소식도 버리지 않습니다.

틱은 `--seen` 없이 읽으므로 같은 카드가 다시 옵니다. 닫은 소식은 run과 종류로 기억해 다시 넣지 않습니다. 닫기는 kairos를 호출하지 않습니다.

### 새 일 기준 저장

기준은 `floor`, 본 ID(200개까지), 센 가장 큰 ID, 아직 보지 않은 수로 이루어집니다. 본 ID가 넘치면 버리는 ID까지 `floor`를 당기고, 그 아래의 보지 않은 일은 본 것으로 칩니다. 기준은 `marks` atom(`persist: 'storage'`)으로 플러그인 저장소에 둡니다. 워커가 같은 값을 읽어 상태 표시줄에 점을 찍습니다.

### 알림에서 열기

1. 알림을 누르면 `KairosNotifier`가 `kairos reveal <id>...`를 호출합니다. kairos는 홈에 `reveal.json`(`{items, at}`)을 쓰고 패널을 엽니다. `next --json`은 10분 안의 값을 `reveal`로 싣습니다.
2. 워커는 kairos 홈 폴더를 `fs.watch`로 감시합니다. 원자적 쓰기는 파일을 교체하는 방식이라 파일이 아니라 폴더를 감시합니다. 이름이 `reveal.json`인 변화만 골라, 150ms 동안 잠잠해진 뒤 한 번 `kairos.reveal`로 알립니다. 내용은 읽지 않습니다.
3. 패널은 `kairos.reveal`을 받으면 검색을 닫고 `지금` 탭으로 돌아온 뒤 `--seen`으로 다시 읽습니다. `지금` 탭으로 돌아오는 것은 대상이 카드 안에 있어도 보이게 하려는 것이고, `--seen`으로 읽는 것은 알림을 눌렀다는 것이 곧 사용자가 직접 봤다는 뜻이기 때문입니다. 닫혀 있던 패널은 열릴 때의 읽기에서 같은 값을 받습니다.

- 홈이 없거나 감시가 끊기면 오류 코드만 남기고 다음 폴링에서 다시 감시를 겁니다. 점검 실행과 대부분의 테스트에서는 감시하지 않습니다.
- `--seen` 읽기가 진행 중일 때 들어온 틱은 읽지 않습니다. 틱이 그 응답을 버리게 되면 누른 알림이 보류한 틱 뒤로 밀리기 때문입니다.
- 알림 대상은 반영이 끝난 값에 적용합니다. 펼친 행이 틱을 보류하고 있다면 반영된 뒤에 적용됩니다. 지금 볼 일이나 목록을 읽지 못한 응답에는 적용하지 않고 `at`도 기록하지 않습니다. 다음에 읽은 값이 같은 알림을 적용합니다.
- 적용한 `at`은 `revealAt` atom(`persist: 'plugin'`)에 저장해 같은 알림을 한 번만 적용합니다. 패널을 다시 열어도 다시 적용하지 않습니다.

## 보안

패널은 외부에서 온 글을 텍스트로만 그리고, 명령 인자로 넘기지 않습니다.

### 화면에 그리는 값

- 제목은 패널의 `Text`와 `ListItem title`로만 그립니다. `Markdown`, `Link`, `Image`는 쓰지 않습니다. Slack 원문 표기는 `displayTitle`이 사람이 읽기 좋은 형태로 바꿉니다.
- 주소는 텍스트로 그리지 않습니다. 사용자가 `원문 열기`를 눌렀을 때만 `shell.openExternal`로 열고, 자동으로 열지 않습니다. 버튼은 `openableUrl`을 통과한 주소에만 그립니다.
- 허용 호스트는 `github.com`, `*.slack.com`, `calendar.google.com`, `mail.google.com`, `notion.so`, `*.notion.so`입니다. https만 받고, 계정 정보나 포트가 있으면 거절합니다. `shell.openExternal`은 권한이 필요 없고 Orca가 사용자에게 확인을 받습니다.

### 워커와 kairos로 보내는 값

- 외부에서 온 제목과 URL은 인자, 셸, 입력창, 세션 프롬프트로 전달하지 않습니다. 워커에는 항목 ID와 고정 버튼 이름만 전달합니다.
- 사용자가 입력한 글 가운데 인자가 되는 것은 패널에 직접 입력한 할 일 제목(`add`)뿐입니다. 셸을 거치지 않고 `--` 뒤에 두므로 옵션으로 해석되지 않습니다. 패널로 전달하는 값에는 `argv`가 없습니다.
- 다시 볼 때 고르기는 고정 버튼 이름(`later_hour`, `later_tomorrow`)만 보냅니다. `--when`의 값은 워커가 정한 두 낱말뿐입니다.
- 읽기의 기록 범위는 패널이 보내는 참거짓 두 값(`seen`, `ready`)으로만 정합니다. 워커는 참인지만 보고, 고정된 인자 세 벌 가운데 하나를 고릅니다. 둘 다 참이면 `seen`을 따릅니다.
- 검색어는 패널 안에서만 씁니다. 워커와 kairos로 보내지 않고, 정규식이 아니라 글자 포함으로 비교합니다.

### 받는 값 검사

- `why`의 규칙 ID는 `^[a-z0-9_]{1,16}\.[a-z0-9_]{1,40}$`로, 사실 코드는 `^[a-z][a-z_]{0,31}$`로 검사합니다. 사실 코드는 16개까지 받습니다. 둘 다 패널의 고정 표에 있는 것만 그립니다.
- `why.offer`의 저장소는 `owner/name` 모양으로, 기준 브랜치는 `origin/`과 안전한 글자로 검사합니다. 하나라도 틀리면 근거만 버리고 버튼과 범위는 그대로 남깁니다. 저장소와 브랜치는 `KeyValue`의 코드 글자로만 그립니다.
- `sources`는 소스 이름을 `^[a-z][a-z0-9_]{0,31}$`로, 상태를 정해진 다섯 값으로 검사해 12줄까지 받고, 틀린 줄은 버립니다. 이름표는 `Text`로만 그리고, 상태는 패널의 고정 낱말로 바꿔 그립니다.
- `reveal.json`은 워커가 읽지 않습니다. 패널이 받는 `reveal`은 `next --json`을 거친 값입니다. ID는 `^[1-9]\d{0,14}$`로 20개까지, 시각은 양수만 받고, 하나라도 틀리면 통째로 버립니다. 알림 앱과 `reveal.json`에는 고정 문구와 ID만 있고 외부 제목과 URL은 없습니다.

### 저장소, 로그, 경로

- 플러그인 저장소에는 패널이 `marks` 하나만 씁니다. ID와 수뿐이고 제목과 주소는 없습니다. 워커는 읽기만 하고, 모양이 틀리면 버립니다.
- `orca.log`에는 오류 코드만 남깁니다. `kairos.tick`과 `kairos.reveal`에는 시각만 들어 있습니다.
- 경로는 `src/paths.ts`의 상수(`KAIROS_BIN`, `KAIROS_HOME`)입니다. `settings:own` 권한을 쓰지 않으려고 설정이나 패널 입력으로 받지 않습니다. `KAIROS_HOME` 환경 변수로 홈을 옮긴 설치에서는 감시가 동작하지 않고, 이때는 패널을 열 때의 읽기가 알림을 받습니다.

| `src/text.ts` | 표시 문자열, Slack 표기 정리, 허용 호스트 판정, 사용자 문구, 이유와 근거와 권장 문구, 제안 문구, 검색어 |
| `src/status.ts` | 상태 표시줄 값 |

### 테스트

이 폴더에서 실행하세요.

```sh
orca plugin validate . --json
orca plugin test . --json
orca plugin check . --json
```

- 세 명령은 로컬에서만 실행되고 Orca에 업로드하지 않습니다.
- `orca plugin check`는 버튼을 누를 수 없습니다. 그래서 처리 중, 처리 실패, 펼친 행, `지금`이 아닌 탭, 검색은 `src/panel.test.tsx`로 확인합니다. [스토리북](../../storybook/README.md)에서는 탭을 눌러 볼 수 있습니다.
- `orca plugin check`는 워커를 실제로 띄웁니다. 그래서 `ORCA_PLUGIN_CHECK_PANELS`가 있으면 kairos를 호출하지 않습니다.
- 테스트는 `startWorker`에 가짜 실행기를 넘겨서 돌립니다.
- `orca plugin types`가 `.orca/types`를 만듭니다. `tsconfig.json`이 이 폴더를 extends합니다. git은 이 폴더를 무시합니다.

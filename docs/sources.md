# 소스

| 소스 | 경로 | 주기 |
|---|---|---|
| Calendar | 수집 모드, `list_events` | 3분, 30분, 하루 |
| GitHub | `gh` 직접 실행 | 3분 |
| Slack | 수집 모드, 검색 | 3분 |
| Gmail | 수집 모드, `search_threads`(Notion 알림 메일 제외) | 60분 |
| Notion | 수집 모드, Gmail의 `notify@mail.notion.com` 메일 | 15분 |

GitHub 노드 읽기 실패는 그 노드를 후보로 가진 질의만 partial로 만든다. 형식 오류나 시간 초과로 실패한 묶음은 같은 수집 안에서 최대 8조각으로 나눠 다시 읽는다(한 수집에 추가 호출 24번까지, 노드 읽기는 시작 뒤 18초까지). 혼자 읽어도 출력 상한을 넘는 노드와 넓게 읽어도 잘린 노드는 넘기고 전진한다(`node_quarantined`, 덮지 못한 구간으로 고지). 다시 읽으면 읽힐 수 있는 노드라도 그 질의가 다른 질의보다 30분 뒤처졌거나 partial이 2시간 이어지면 넘긴다. 넘긴 스냅샷 질의는 읽지 못한 객체를 빠진 것이나 닫힌 것으로 보지 않는다. 한도(2차 한도 포함)와 인증 실패는 노드와 무관한 실패라 넘기지 않고 다음 틱에 다시 읽는다.

Calendar의 `[배포]` 일정은 주최자가 나(또는 배포 캘린더 자신)이거나 신뢰 도메인, 목록의 그룹 캘린더일 때만 배포로 본다. 주최자가 없거나 주소가 비면 일반 일정(T3)으로 둔다.

Notion은 알림함 도구가 없어 알림 메일을 읽는다. 검색으로 새 스레드를 찾고, 모드가 같은 틱의 검색 결과로만 `get_thread`를 부른다. 틱당 12건, 동시 4개다. 메일의 페이지 블록마다 이벤트 1건을 만들고 멘션과 내 이름은 P1, 댓글은 P2, 편집과 인기·추천 메일은 기록만이다. 본문, 댓글 내용, 메일 제목, 추적 링크는 저장하지 않는다. 다른 소스의 앞부분 120자도 링크와 메일 주소는 `[링크]`, `[주소]`로 바꿔 저장한다. 읽지 못한 스레드는 다음 틱에 다시 읽고 그동안 `partial`이다. 같은 스레드가 한 시간 넘게 5회 이상 실패하면 격리하고 덮지 못한 구간으로 고지한다. 공백이 이틀을 넘으면 최근 이틀은 매 틱 읽고, 그보다 오래된 메일은 오래된 쪽부터 이틀씩 읽는다. 동작 문구를 못 찾은 블록은 `notion_unknown`이고 제목 없이 P2로 열린다. 내용에 내 이름이 있으면 P1이다. 24시간에 3건 이상이면 `doctor` 문제와 감시자 경보가 된다. Notion이 메일을 보내지 않은 일은 kairos도 모른다.

약 50KB를 넘는 MCP 응답은 Claude Code가 `~/.claude/projects/<collect-cwd 슬러그>/<세션>/tool-results/`에 원문으로 남긴다. `kairos ingest`가 그 폴더 안의 파일만 되찾아 지우고, `kairos collect`가 끝날 때와 수집 시간 밖의 틱에서 남은 파일을 지운다. 다음 쪽 값은 `kairos page-info`가 같은 경로 검사로 읽어 훅에 돌려준다. 남은 파일은 `doctor`의 `큰 응답 임시 파일` 줄과 problems, 감시자 경보로 나온다.

## 잠자기

Mac이 잠든 틱은 고장이 아니다. 심장박동 공백이 30초 이상이거나 `pmset -g stats`의 잠자기 횟수가 틱 사이에 늘었으면, 그 틱의 `timeout` 행만 `error_code`를 `sleep_interrupted`로 바꾼다. `outcome`과 cursor는 그대로다. 수집 요약의 실패 건수와 `doctor` 문제에서 빠지고 소스 줄에 코드만 나온다.

깨어난 시각은 `resumed.at`에 초 단위로 남고 건강 판정과 감시자의 하한이 된다. 감시자는 자기 실행 간격이 7분 30초를 넘으면 깨어난 것으로 보고 같은 파일에 쓴다. 깨어난 뒤 허용 지연이 지나도 수집이 없으면 그대로 경고한다.

# 소스

| 소스 | 수집 경로 | 주기 |
|---|---|---|
| Calendar | 수집 모드, `list_events` | 3분, 30분, 하루 |
| GitHub | `gh` 직접 실행 | 3분 |
| Slack | 수집 모드, 검색 | 3분 |
| Gmail | 수집 모드, `search_threads`(Notion 알림 메일 제외) | 60분 |
| Notion | 수집 모드, Gmail로 온 `notify@mail.notion.com` 메일 | 15분 |

## GitHub

노드 하나를 읽지 못하면 그 노드를 후보로 가진 질의만 partial이 된다.

- 형식 오류나 시간 초과로 실패한 배치는 같은 수집 안에서 최대 8조각으로 나눠 다시 읽는다. 한 번의 수집에서 추가 호출은 24번까지이고, 노드 읽기는 시작 후 18초까지만 한다.
- 단독으로 읽어도 출력 상한을 넘는 노드와, 범위를 넓혀 읽어도 잘리는 노드는 건너뛰고 진행한다(`node_quarantined`, 읽지 못한 구간으로 알린다).
- 다시 읽으면 읽힐 수 있는 노드라도, 그 질의가 다른 질의보다 30분 뒤처졌거나 partial이 2시간 동안 이어지면 건너뛴다.
- 건너뛴 스냅샷 질의는 읽지 못한 객체를 빠졌거나 닫힌 것으로 판단하지 않는다.
- 요청 한도(2차 한도 포함)와 인증 실패는 노드와 무관한 실패이므로 건너뛰지 않고 다음 틱에 다시 읽는다.

## Calendar

`[배포]` 일정은 주최자가 본인(또는 배포 캘린더 자체)이거나, 신뢰 도메인 소속이거나, 목록에 있는 그룹 캘린더일 때만 배포로 인정한다. 주최자가 없거나 주소가 비어 있으면 일반 일정(T3)으로 둔다.

## Notion

Notion에는 알림함을 읽는 도구가 없어서 알림 메일을 읽는다.

- 검색으로 새 스레드를 찾고, 같은 틱의 검색 결과에 있는 스레드에만 `get_thread`를 호출한다. 틱당 12건, 동시 4개까지다.
- 메일의 페이지 블록마다 이벤트 1건을 만든다. 멘션과 내 이름은 P1, 댓글은 P2이고, 편집과 인기·추천 메일은 기록만 한다.
- 본문, 댓글 내용, 메일 제목, 추적 링크는 저장하지 않는다. 다른 소스에서 저장하는 앞부분 120자도 링크와 메일 주소를 `[링크]`, `[주소]`로 바꿔 저장한다.
- 읽지 못한 스레드는 다음 틱에 다시 읽고, 그동안은 `partial`이다. 같은 스레드가 한 시간 넘게 5회 이상 실패하면 격리하고 읽지 못한 구간으로 알린다.
- 공백이 이틀을 넘으면 최근 이틀은 매 틱 읽고, 그보다 오래된 메일은 오래된 것부터 이틀 단위로 읽는다.
- 동작 문구를 찾지 못한 블록은 `notion_unknown`이 되고 제목 없이 P2로 열린다. 내용에 내 이름이 있으면 P1이다. 24시간 안에 3건 이상 생기면 `doctor` 문제와 감시자 경보로 알린다.
- Notion이 메일을 보내지 않은 일은 kairos도 알 수 없다.

## 큰 MCP 응답

약 50KB를 넘는 MCP 응답은 Claude Code가 `~/.claude/projects/<collect-cwd 슬러그>/<세션>/tool-results/`에 원문 파일로 남긴다.

- `kairos ingest`가 그 폴더 안의 파일만 회수한 뒤 지운다.
- `kairos collect`가 끝날 때와 수집 시간 밖의 틱에서 남은 파일을 지운다.
- 다음 페이지 값은 `kairos page-info`가 같은 경로 검사를 거쳐 읽은 뒤 훅에 돌려준다.
- 남은 파일은 `doctor`의 `큰 응답 임시 파일` 줄과 problems, 감시자 경보로 알린다.

## 잠자기

Mac이 잠든 동안의 틱은 고장으로 보지 않는다.

- 하트비트 공백이 30초 이상이거나 `pmset -g stats`의 잠자기 횟수가 틱 사이에 늘었으면, 그 틱의 `timeout` 행만 `error_code`를 `sleep_interrupted`로 바꾼다. `outcome`과 cursor는 그대로 둔다.
- 이 틱은 수집 요약의 실패 건수와 `doctor` 문제에서 빠지고, 소스 줄에 코드만 나온다.
- 깨어난 시각은 `resumed.at`에 초 단위로 남는다. 상태 판정과 감시자가 이 시각을 하한으로 쓴다.
- 감시자는 자기 실행 간격이 7분 30초를 넘으면 깨어난 것으로 보고 같은 파일에 기록한다.
- 깨어난 뒤 허용 지연이 지나도 수집이 없으면 그대로 경고한다.

# 에이전트 세션

kairos가 고른 일 가운데 일부는 claude 세션에 맡길 수 있습니다. 담당 이슈를 고치거나, 리뷰 의견이나 답변 초안을 쓰는 일입니다. 세션은 샌드박스 안에서만 일하고 외부에 글을 쓰지 못합니다.

이 문서는 세션을 켜고 쓰는 방법을 설명합니다. 세션이 어떻게 제한되는지는 [세션 샌드박스](session-sandbox.md)에, 보안 기준은 [SECURITY.md](../SECURITY.md)에 있습니다.

## 세션이 하는 일

어떤 일을 맡길지는 항목이 열린 이유에 따라 정해집니다. 이 종류를 [플레이북](concepts.md#플레이북)이라고 부릅니다.

| 플레이북 | 대상 | 세션이 하는 일 | 프로필 |
|---|---|---|---|
| `qa_issue` | 내 담당 이슈 | 원인 조사, 수정 계획, 수정과 로컬 커밋 | 고치는 프로필 |
| `pr_review` | 리뷰를 요청받은 PR | 리뷰 의견 초안 | 읽는 프로필 |
| `reply_draft` | 답장이 필요한 이슈 | 답변 초안 | 읽는 프로필 |

- `qa_issue`는 조사와 계획을 마친 뒤 해당 worktree에서 코드를 고치고 로컬에 커밋합니다.
- 읽는 프로필의 결과물은 세션 안에 남습니다.
- push, PR, 코멘트, Notion처럼 외부에 쓰는 플레이북은 없습니다. 고치는 세션의 커밋은 사용자가 [PR 올리기](#pr-올리기)를 누를 때만 세션 밖에서 올라갑니다.

## 맡길 수 있는 일

세션에 맡길 수 있는 항목은 `playbook_of`가 정합니다. 다음 조건을 모두 만족해야 합니다.

- 열린 이슈나 PR이고, 본인(T0)이나 조직의 사람(T1)이 열었습니다. 매핑표에 있는 저장소이고 URL 형식도 맞습니다(`playbook_for`).
- kairos가 본 그 이슈의 사람 글이 모두 T0나 T1의 것입니다. 한 번이라도 T2나 T3의 글을 봤다면 `outsider_marks`에 남아, 보존 기한과 정리 작업이 지나도 계속 막습니다.
- 처음 읽을 때 최근 20개에 들지 않았던 글과 마지막 수집 뒤에 달린 글은 세션을 띄우기 직전에 다시 확인합니다.

조건에 맞지 않는 항목은 `not_eligible`과 표시용 URL만 돌려받고, Orca를 호출하지 않습니다. 신뢰 등급은 [핵심 개념](concepts.md#신뢰-등급)에 있습니다.

제안은 이슈마다 하나이고, 플레이북이 있는 첫 번째 열린 항목에 붙습니다. 그 이슈에 이미 세션이 있으면 제안하지 않습니다. 시작 버튼은 여기에 더해 세션 잠금이 풀려 있어야 나옵니다. 잠겨 있으면 목록에 `playbook`과 `scope`만 나오고 `start`는 없습니다.

다음 항목은 제안하지 않습니다.

- Slack, Gmail, Notion, Calendar 항목. 세션은 그 소스를 읽을 방법이 없고(`--strict-mcp-config`), kairos는 본문을 저장하지 않으므로 넘겨줄 내용도 없습니다.
- 내 PR의 CI 실패와 변경 요청, PR에 달린 글. 세션에서는 `gh run`과 `gh api`가 막혀 있어 CI 로그와 인라인 리뷰 글을 읽을 수 없습니다.

## 세션 켜기

세션은 처음에 잠겨 있습니다. [세션 잠금](concepts.md#세션-잠금)은 차단 테스트를 하기 전에 세션이 열리는 일을 막습니다. 아래 순서로 켜세요.

1. [세션 토큰](#세션-토큰)을 만들어 등록합니다.
2. [차단 테스트](#차단-테스트)로 외부 쓰기가 실제로 막히는지 확인합니다.
3. `kairos sessions on`을 실행합니다.

현재 상태는 `kairos doctor`의 `세션` 줄에 나옵니다. `kairos sessions off`로 끄면 시작 버튼이 사라집니다.

켤 때의 설정 지문은 `session-approval`에 남습니다. 세션 자격에 영향을 주는 설정(조직, 신뢰 도메인, 본인 식별자, 플레이북 대상, 호스트, MCP로 연 동작)이 바뀌면 세션이 다시 잠깁니다. 그때는 차단 테스트를 다시 확인하고 `kairos sessions on`을 실행하세요.

### 세션 토큰

세션이 쓰는 GitHub 권한은 읽기 전용 fine-grained 토큰(`github_pat_`) 하나뿐입니다.

1. GitHub에서 fine-grained 토큰을 만듭니다. 저장소는 플레이북 대상 저장소만 고르고, 권한은 Contents, Issues, Pull requests, Metadata 모두 Read-only로 둡니다.
2. 토큰을 stdin으로 넘겨 키체인에 저장합니다.

   ```sh
   kairos connect session-token < 토큰파일
   ```

키체인에 토큰이 없으면 `<KAIROS_HOME>/session-gh-token` 파일을 읽습니다. 이 파일은 본인 소유의 0600 일반 파일이어야 하고, 토큰 한 줄만 들어 있어야 합니다.

토큰이 없거나 형식이나 권한이 맞지 않으면 `kairos-run`은 claude를 띄우지 않고 고정 문구로 거절합니다. classic 토큰(`ghp_`)과 gh 로그인 토큰(`gho_`)은 쓰기 범위가 함께 들어 있어서 받지 않습니다.

### 차단 테스트

세션을 켜기 전에 실제 세션을 하나 띄워 직접 확인하는 점검입니다. CLI 메시지에는 '차단 시험'으로 나옵니다.

- [ ] 세션이 확인 창 없이 뜨고 `worktree ps`에 잡힌다
- [ ] 세션 안에서 `printenv`를 실행하면 지워야 할 환경 변수가 비어 있다
- [ ] 메시지 전송 도구, gh 쓰기, git push 같은 외부 쓰기가 모두 막힌다

> [!IMPORTANT]
> 외부 쓰기 시험은 회사 저장소가 아니라 개인 테스트 저장소와 로컬 bare 원격으로 하세요.

## 세션 시작하기

패널의 `세션 열고 시작` 버튼이 `kairos accept <id>`를 호출합니다. 같은 항목에 여러 번 호출해도 결과는 같습니다. 세션은 이슈마다 하나이므로, 같은 이슈의 다른 항목으로 연 세션이 있으면 그 세션으로 보냅니다.

시작할 수 없으면 다음 코드를 돌려줍니다.

| 코드 | 뜻 |
|---|---|
| `gate_closed` | 표시 게이트가 닫혀 있습니다 |
| `not_eligible` | 세션이 잠겨 있거나 맡길 수 없는 항목입니다. URL만 함께 옵니다 |
| `session_caller` | 세션이나 Orca 터미널 안에서 호출했습니다 |

세션 창은 `kairos accept`가 터미널을 만들 때 한 번만 앞으로 나옵니다. 사용자가 버튼을 누른 순간이고, 자동 경로는 이 호출에 도달하지 않기 때문입니다. 그 뒤로는 `kairos move <id>`만 세션으로 데려갑니다. `move`는 paneKey로 handle을 다시 찾아 `orca terminal switch`를 호출하고, 터미널이 없으면 run을 `ended`로 기록합니다.

`kairos accept <id> --cancel`은 항목을 되돌리지만 이미 뜬 세션을 끄지는 않습니다. 끝났거나 확인이 필요한 세션의 항목에는 패널에 `되돌리기`로 나옵니다.

Orca를 어떤 순서로 호출하는지는 [세션 샌드박스](session-sandbox.md#수락-순서)에 있습니다.

## 세션 상태

`kairos runs`가 Orca의 `worktree ps`를 읽어 run 상태를 맞춥니다. 패널은 `next --json`의 `runs.active`가 0보다 클 때 이 명령을 호출하고, 수집 틱은 호출하지 않습니다. 항목이 먼저 닫혀도 세션은 계속 추적합니다.

| ps | run |
|---|---|
| working | `started` |
| waiting, blocked | `waiting_user`, 준비됨 카드 `question` |
| done | `waiting_user`, 준비됨 카드 `done` |
| 터미널을 만든 뒤 30초 동안 보이지 않음 | `needs_attention`, 카드 `attention` |
| 한 번 보인 뒤 사라지고 터미널도 없음 | `ended`, 카드 `ended` |
| ps 실패, 잘린 응답 | 바꾸지 않음 |

- claude가 끝나면 run을 `ended`로 기록합니다. ps에 잡히기 전에 실패로 끝나면 `failed`로 내리고 항목을 되돌립니다.
- `kairos-run`이 시작하지 않은 채 5분이 지난 `needs_attention`과, 터미널 단계까지 가지 못한 채 5분이 지난 `claimed`는 `failed`로 내리고 항목을 되돌립니다.
- 세션이 끝났다고 항목이 끝나지는 않습니다.
- 이미 내려간 run은 다시 끝나도 항목을 건드리지 않습니다.

### 준비됨 카드

세션이 답을 기다리거나, 끝나거나, 확인이 필요하거나, 실패하면 `next --json`의 `ready` 배열에 준비됨 카드가 나옵니다.

- 예산과 상관없이 run마다 한 번만 나옵니다. 패널이 `--seen`이나 `--seen-ready`로 그리면 다시 나오지 않습니다.
- 항목이 닫혀도 세션이 살아 있으면 나옵니다.
- 표시 게이트가 닫혀 있으면 `failed` 카드만 나옵니다.
- 백그라운드에서 실패한 세션은 `failed` 카드를 한 번 내고, 항목은 다음 묶음에 다시 올라옵니다.

## PR 올리기

고치는 세션(`qa_issue`)은 샌드박스 안에서 로컬 커밋까지만 하고, PR은 제안만 합니다. 첫 커밋의 제목이 PR 제목이 되고, 커밋 본문(커밋이 여러 개면 커밋 목록)이 PR 본문이 됩니다.

세션이 끝나면 패널에 `PR 올리기`가 나옵니다. 누르면 `kairos pr <id>`가 세션 밖에서 사용자의 git 자격 증명과 gh 로그인으로 push하고, 플레이북 대상 저장소에 draft PR을 만듭니다. 브랜치는 run ID로 정한 `kairos/<worktree 이름>`입니다.

- 확인한 커밋 SHA를 그대로 올립니다. 커밋하지 않은 변경은 포함하지 않습니다.
- 본인이 연 PR이 이미 있으면 push만 합니다.
- 제목의 멘션, 이슈 참조, 링크는 무력화하고, 커밋 메시지는 본문의 코드 블록 안에만 싣습니다.
- 세션 안에서는 호출할 수 없습니다.

다음 경우에는 올리지 않습니다.

- kairos-run이 띄운 세션이 아닙니다. 이어받은 세션은 올리지 않습니다.
- 저장소나 worktree 설정이 git이 실행하는 명령이나 원격 주소를 바꿉니다.
- origin이 대상 저장소가 아닙니다.
- 원격에서 방금 받은 base와 비교해 `.github/` 같은 CI와 리뷰 설정을 바꾼 커밋이 있습니다.
- 받은 base ref가 `git ls-remote`가 알려 준 SHA와 다릅니다. base ref는 같은 클론의 다른 세션도 쓰는 공용 refs에 있기 때문입니다.

> [!WARNING]
> PR을 올리면 대상 저장소의 CI가 세션이 쓴 코드를 저장소 비밀과 함께 실행할 수 있습니다. CI 설정 경로는 막지만 `package.json` 같은 빌드 스크립트는 막지 않습니다. 누르기 전에 세션의 변경을 확인하세요. 같은 클론에서 고치는 세션을 여러 개 돌렸다면 [SECURITY.md](../SECURITY.md#pr을-올릴-때)의 남은 위험도 읽어 보세요.

# 항목과 표시

`kairos collect`가 끝날 때 저장된 이벤트로 항목을 갱신한다. 엔진이 실패해도 수집 기록과 `state.json`은 남고, 코드는 `engine.json`과 `doctor`에 나온다. 이벤트 한 건의 예외는 그 건만 건너뛰고 `event_skipped`로 남긴 뒤 다음 틱에 다시 본다.

- 처분이 opened이고 baseline이 아닌 이벤트가 `(object_key, reason)` 항목 하나에 붙는다. 객체가 없는 Slack은 스레드가 키다.
- 항목은 붙은 이벤트가 모두 닫혀야 닫힌다. 이벤트 종료는 ok 실행의 양성 증거나 시각 경과뿐이다. 회의의 취소와 철회만 그 자리에서 항목을 withdrawn으로 닫고, 이때도 그 소스가 이번 틱에 ok여야 한다.
- 붙은 이벤트가 없는 항목(기준선과 거기서 올라온 항목)은 객체의 이벤트로 직접 판정한다.
- 접힌 댓글은 새 항목을 만들지 않고 이력으로 붙는다. 할일로 남겨 조용히 대기 중인 항목은 깨운다. 사용자가 닫은 항목의 이벤트는 접는 기준에서 빠져 다음 댓글이 새 항목이 된다.
- `work_owed`, `manual`은 사용자 조작으로만 닫힌다. `closed`는 되살리지 않고 같은 일은 새 행이다.
- P0는 `RULES`에서만 온다. 스키마가 P0의 reason과 근거 이벤트를 강제한다.
- 외부 제목은 항목에 복사하지 않는다. `items.title`은 `kairos add`의 입력만 받고 저장만 한다.

표시 게이트는 `kairos display`로 바꾼다. 기본 auto는 첫 정상 수집 뒤 기록 1근무일이 끝나는 20:00 KST까지 카드와 알림을 내지 않는다. 한 번 열리면 `control.json`의 `displayOpenedAt`으로 고정되어 쉬는 날을 사후에 넣어도 닫히지 않는다. 기록과 항목 엔진은 게이트와 무관하게 돈다. `kairos pause`도 게이트를 닫는다.

예산은 지금 카드 1장에만 쓴다. 상태 표시줄 건수, 패널 목록, Mac 알림은 빠진다.

| 규칙 | 값 |
|---|---|
| P1 | 시간당 1건, 하루 4건. 초과분은 다음 묶음 |
| 같은 채널 30분 | 카드 1장, 예산 1건 |
| 밀어내기 | 2회. 응답 없이 60분이 지난 노출과 `나중에`가 1회씩이다. 보류로 가려진 시간은 세지 않고 카드를 내린다 |
| 근무일을 넘긴 P1 | 다음 근무일 첫 카드 맨 앞, `+N`에 접지 않음 |
| P2 묶음 | 13:30 이후와 18:00 이후 각 1회, 7줄 넘으면 `+N` |
| 보류 | 포커스, 12:00~13:30, 10:00~19:30 밖, 쉬는 날. P0는 넘는다 |

`next`는 고르기만 하고 몇 번을 불러도 예산을 쓰지 않는다. `--seen`을 주면 `suggestions`와 예산에 남는다. 패널은 연 순간과 버튼, 새로고침에만 주고 60초 틱에는 주지 않는다. `--json`의 형식 번호는 `src/next.ts`의 `CONTRACT_VERSION`이다. 상태 표시줄은 60초마다 `next --json`으로 읽는다. `state.json`의 `items`, `gate`, `runs`는 감시와 조회용이다.

새 P0는 `collect` 끝에서 1회 알린다. 제목은 `긴급`, 본문은 `회의 임박 1건, 배포 당일 위험 1건`처럼 고정 문구와 건수뿐이다. 게이트가 닫혀 있거나 전달이 실패하면 표시를 남기지 않아 다음 틱에 다시 시도한다. 미전달 건수는 `doctor` 문제로 나온다.

새 P1도 `collect` 끝에서 P0 다음에 알린다. 제목은 `새로 온 일`, 복귀 묶음이면 `자리를 비운 사이 온 일`이다. 패널 플러그인은 알림 권한을 쓰지 않는다. 본문은 `Slack 멘션 2건, GitHub 리뷰 요청 1건`처럼 소스와 규칙별 고정 낱말과 건수뿐이고 제목, 이름, 채널 이름, 메시지는 넣지 않는다. 한 틱의 여러 건은 알림 한 번이다. 시간당 1건 제한은 받지 않고, 지금 카드 예산도 쓰지 않으며, 수집 주기는 그대로다. 새 P1은 항목이 처음 P1이 된 때다. P2 항목이 P1로 오른 경우와 기준선 항목이 사람의 새 사건으로 올라온 경우도 든다. 한 항목은 한 번만 알린다.

| 때 | 동작 |
|---|---|
| 평시 | 틱 끝에서 알림 |
| 같은 채널에서 앞선 알림 뒤 30분 안 | 그 알림에 묶고 따로 울리지 않음. 구간은 실제 알림 시각에서만 잰다. 채널이 없는 GitHub 같은 소스는 같은 객체를 같은 채널로 본다. 다른 객체는 묶지 않는다 |
| 잠자기나 재부팅 뒤 복귀 | 수집 틱의 공백이 6분을 넘거나 틱이 얼어붙었으면 복귀다. 복귀 뒤 30분 안에 나간 알림은 이후 30분 동안 공백 안에서 일어난 건을 소스와 무관하게 묶는다. 복귀 뒤에 일어난 건은 따로 알림. 밤과 주말의 공백, 근무일 아침의 첫 틱은 복귀가 아니다 |
| 틱이 잠자기에 얼어붙음 | 그 틱은 알리지 않고 다음 틱이 그때의 시각으로 판단 |
| 포커스, 12:00~13:30, 10:00~19:30 밖 | 쌓았다가 끝난 뒤 첫 틱에 한 번에 알림. 앞선 알림의 30분 구간에 묶지 않고 건수에 넣는다. 그사이 일시정지나 쉬는 날이 끼어도 사라지지 않고 열린 뒤 첫 틱에 알림 |
| 표시 게이트 닫힘, 일시정지, 쉬는 날 | 그때 처음 잡힌 건은 다시 열려도 울리지 않고 패널에 남음. 앞서 보류했거나 전달에 실패한 건은 남겨 열린 뒤 알림 |
| `kairos notify off` | 기다리던 건까지 모두 알리지 않음. 다시 켜도 울리지 않고 패널에 남음 |
| 닫힘, 대기, 수락, 패널에서 이미 본 항목, 기준선 | 알리지 않음 |
| 이미 알린 P1이 남김이나 배포 때 다시로 대기했다가 깨어남 | 알리지 않음. 각 항목은 한 번이다. 패널에는 나옴 |
| 전달 실패 | 표시를 남기지 않고 세 번은 틱마다, 뒤의 두 번은 30분 간격으로 시도. 모두 5번이고 그 뒤는 시도하지 않음. `doctor`의 `P1 알림` 줄과 problems에 미전달로 나옴. 수집 틱은 실패하지 않음 |

`collect`의 보고와 `doctor`의 `P1 알림 오늘` 줄에 전달, 묶음, 미발송 건수가 나온다. `items.p1_notice`가 표시의 이유를 가른다. 스키마 v6 이전은 그때 이미 있는 P1에 표시를 채운다. 기능을 배포하는 순간에는 울리지 않는다. v7 이전은 기다리던 건을 보류로 잇는다. `doctor`의 보류 건수는 기다리는 정상 상태라 문제로 올리지 않는다. `kairos notify off`는 P1만 끄고 P0와 건강 경고는 끄지 못한다.

알림은 헬퍼 `ops/notifier/KairosNotifier.app`만 보낸다. osascript는 쓰지 않는다. 그 알림은 '스크립트 편집기' 이름으로 뜨고 누르면 Script Editor가 열린다. 실행 파일은 `KAIROS_NOTIFIER`가 있으면 그 값, 없으면 설치 자료 폴더의 번들이다. 헬퍼에는 `post '<json>'`으로 제목, 본문, 항목 ID, 급만 넘긴다. 헬퍼가 없거나 권한이 없거나 실패하면 보내지 못한 것으로 두고 다음 틱이 다시 보낸다. 감시자(`ops/kairos-watchdog.zsh`)도 같은 헬퍼로 `kairos 점검` 알림을 보낸다. 헬퍼 권한은 `KairosNotifier setup`을 한 번 실행해 받는다. 백그라운드 틱은 권한 대화상자를 띄우지 않는다. 설치는 `ops/notifier`에 번들만 놓는다. 소스와 `.build`는 가져가지 않고, 번들은 임시 이름으로 복사한 뒤 바꿔 끼운다. 세션 거부 목록에는 헬퍼 실행 파일의 이름과 설치 경로가 들어 있다.

헬퍼 알림을 누르면 헬퍼가 `kairos reveal <ID>...`를 부른다. reveal은 ID 1~20개를 검사하고 `reveal.json`(`{"items":[..],"at":<ms>}`, 0600)을 쓴 뒤 `orca plugin open`으로 패널을 열고 `open -b com.stablyai.orca`로 Orca를 앞으로 끌어온다. Orca가 꺼져 있어 패널을 열지 못했고 끌어오기는 성공했으면, Orca가 뜰 때까지 0.5초 간격으로 8초 동안 패널을 다시 연다. Orca 단계가 실패해도 성공으로 답한다. `next --json`은 10분 안에 쓴 reveal.json만 `reveal` 필드로 싣는다. 형식 번호는 그대로다.

헬퍼의 종료 코드 0을 전달로 본다. 알림 권한이 꺼져 있거나 방해 금지 중이면 화면에 뜨지 않아도 전달로 남는다. 설치 뒤 실제로 뜨는지 한 번 확인한다.

`kairos triage`는 기준선 객체(담당 이슈, 내 PR, 리뷰 요청)를 10건씩 항목 ID가 있는 대기 행으로 만든다. 유지하면 목록에만 남고 사람의 새 사건이나 배포 연결이 생길 때 올라온다.

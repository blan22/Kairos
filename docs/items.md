# 항목과 표시

이 문서의 시각(10:00~19:30, 12:00~13:30, 13:30, 18:00, 20:00)은 기본값이다. `config.toml`의 `[schedule]`로 바꿀 수 있다([설치와 설정](install.md)).

## 항목

`kairos collect`는 수집이 끝날 때 저장된 이벤트로 항목을 갱신한다. 엔진이 실패해도 수집 기록과 `state.json`은 남고, 오류 코드는 `engine.json`과 `doctor`에 나온다. 이벤트 한 건에서 예외가 나면 그 건만 건너뛰고 `event_skipped`로 기록한 뒤 다음 틱에 다시 처리한다.

- 처분이 opened이고 기준선(baseline)이 아닌 이벤트는 `(object_key, reason)`으로 식별하는 항목 하나에 붙는다. 객체가 없는 Slack은 스레드가 키가 된다.
- 항목은 붙어 있는 이벤트가 모두 닫혀야 닫힌다. 이벤트를 닫는 근거는 ok로 끝난 실행에서 확인한 증거이거나 시간 경과뿐이다. 회의 취소와 철회만 예외로, 그 자리에서 항목을 withdrawn으로 닫는다. 이때도 해당 소스가 이번 틱에서 ok여야 한다.
- 붙은 이벤트가 없는 항목(기준선 항목과 거기서 올라온 항목)은 객체의 이벤트를 직접 보고 판정한다.
- 접힌 댓글은 새 항목을 만들지 않고 이력으로 붙는다. 할 일로 남겨 조용히 대기 중이던 항목이 있으면 다시 깨운다. 사용자가 닫은 항목의 이벤트는 접는 기준에서 빠지므로, 그다음 댓글은 새 항목이 된다.
- `work_owed`와 `manual` 항목은 사용자 조작으로만 닫힌다. `closed`가 된 항목은 되살리지 않고, 같은 일이 다시 생기면 새 행으로 만든다.
- P0는 `kairos-policy`의 규칙에서만 나온다. 사용자 입력이나 모델 출력으로는 만들 수 없고, 스키마가 P0의 reason과 근거 이벤트를 강제한다.
- 외부에서 온 제목은 항목에 복사하지 않는다. `items.title`에는 `kairos add`로 입력한 값만 들어가고, 저장하는 용도로만 쓴다.

## 표시 게이트

표시 게이트는 `kairos display`로 바꾼다.

- auto는 첫 정상 수집 뒤 기록 1근무일이 끝나는 시각(수집 시간이 끝나는 20:00)까지 카드와 알림을 내지 않는다. 표시 모드를 고른 적이 없으면 auto다.
- `kairos setup`의 설치 단계는 표시 모드를 고른 적이 없고 표시가 열린 적도 없을 때 on으로 바꾼다. 첫 수집부터 카드와 알림을 내기 위해서다. 직접 고른 값(on, off, auto)은 바꾸지 않는다.
- 한 번 열리면 `control.json`의 `displayOpenedAt`으로 고정된다. 나중에 쉬는 날을 추가해도 다시 닫히지 않는다.
- 기록과 항목 엔진은 게이트와 관계없이 동작한다.
- `kairos pause`도 게이트를 닫는다.

## 예산

예산은 '지금 볼 일' 카드 한 장에만 적용한다. 상태 표시줄의 건수, 패널 목록, Mac 알림에는 적용하지 않는다.

| 규칙 | 값 |
|---|---|
| P1 | 시간당 1건, 하루 4건. 초과분은 다음 묶음으로 넘긴다 |
| 같은 채널 30분 | 카드 1장, 예산 1건 |
| 밀어내기 | 2회. 응답 없이 60분이 지난 노출과 `나중에`를 각각 1회로 센다. 보류로 가려진 시간은 세지 않고 카드를 내린다 |
| 근무일을 넘긴 P1 | 다음 근무일 첫 카드의 맨 앞에 두고 `+N`으로 접지 않는다 |
| P2 묶음 | 13:30 이후와 18:00 이후에 각 1회. 7줄을 넘으면 `+N`으로 접는다 |
| 보류 | 포커스 중, 점심(12:00~13:30), 근무 시간(10:00~19:30) 밖, 쉬는 날. P0는 보류하지 않는다 |

- `next`는 고르기만 한다. 몇 번을 호출해도 예산을 쓰지 않는다. `--seen`을 주면 `suggestions`와 예산에 기록된다.
- 패널은 패널을 연 순간, 버튼, 새로고침에만 `--seen`을 주고 60초 틱에는 주지 않는다.
- `--json` 응답의 형식 번호는 `kairos-agenda`의 `CONTRACT_VERSION`이다.
- 상태 표시줄은 60초마다 `next --json`으로 읽는다. `state.json`의 `items`, `gate`, `runs`는 감시와 조회용이다.

## 알림

### P0

새 P0는 `collect`가 끝날 때 한 번 알린다. 제목은 `긴급`이고, 본문은 `회의 임박 1건, 배포 당일 위험 1건`처럼 고정 문구와 건수뿐이다. 게이트가 닫혀 있거나 전달에 실패하면 알림 표시를 남기지 않으므로 다음 틱에 다시 시도한다. 전달하지 못한 건수는 `doctor`에 문제로 나온다.

### P1

새 P1도 `collect`가 끝날 때 P0 다음에 알린다.

- 제목은 `새로 온 일`이고, 복귀 묶음이면 `자리를 비운 사이 온 일`이다.
- 본문은 `Slack 멘션 2건, GitHub 리뷰 요청 1건`처럼 소스와 규칙별 고정 문구와 건수뿐이다. 제목, 이름, 채널 이름, 메시지는 넣지 않는다.
- 한 틱에 여러 건이 생겨도 알림은 한 번이다.
- 시간당 1건 제한을 받지 않고, '지금 볼 일' 카드의 예산도 쓰지 않는다. 수집 주기는 그대로다.
- '새 P1'은 항목이 처음 P1이 된 시점을 뜻한다. P2 항목이 P1로 올라간 경우와, 기준선 항목이 사람의 새 이벤트로 올라온 경우도 포함한다. 한 항목은 한 번만 알린다.
- 패널 플러그인은 알림 권한을 쓰지 않는다.

| 상황 | 동작 |
|---|---|
| 평상시 | 틱이 끝날 때 알린다 |
| 같은 채널에서 앞선 알림 뒤 30분 안 | 앞선 알림에 묶고 따로 울리지 않는다. 구간은 실제로 알림이 나간 시각부터만 잰다. GitHub처럼 채널이 없는 소스는 같은 객체를 같은 채널로 본다. 다른 객체는 묶지 않는다 |
| 잠자기나 재부팅 뒤 복귀 | 수집 틱의 공백이 6분을 넘거나 틱이 멈춰 있었으면 복귀로 본다. 복귀 뒤 30분 안에 나간 알림은, 이후 30분 동안 공백 중에 일어난 건을 소스와 관계없이 묶는다. 복귀 뒤에 일어난 건은 따로 알린다. 밤과 주말의 공백, 근무일 아침의 첫 틱은 복귀로 보지 않는다 |
| 틱이 잠자기로 멈춤 | 그 틱에서는 알리지 않고, 다음 틱이 그때의 시각으로 판단한다 |
| 포커스 중, 점심(12:00~13:30), 근무 시간(10:00~19:30) 밖 | 쌓아 두었다가 끝난 뒤 첫 틱에 한 번에 알린다. 앞선 알림의 30분 구간에 묶지 않고 건수에 포함한다. 그사이에 일시정지나 쉬는 날이 끼어도 사라지지 않고, 다시 열린 뒤 첫 틱에 알린다 |
| 표시 게이트 닫힘, 일시정지, 쉬는 날 | 그 기간에 처음 잡힌 건은 다시 열려도 울리지 않고 패널에만 남는다. 그 전에 보류했거나 전달에 실패한 건은 유지했다가 열린 뒤에 알린다 |
| `kairos notify off` | 대기 중이던 건까지 모두 알리지 않는다. 다시 켜도 울리지 않고 패널에만 남는다 |
| 닫힘, 대기, 수락, 패널에서 이미 본 항목, 기준선 | 알리지 않는다 |
| 이미 알린 P1이 남겨 두기(`keep`)나 배포 때 다시(`keep --until-deploy`)로 대기했다가 깨어남 | 알리지 않는다. 항목마다 한 번만 알린다. 패널에는 나온다 |
| 전달 실패 | 알림 표시를 남기지 않고 다시 시도한다. 처음 세 번은 틱마다, 이후 두 번은 30분 간격이다. 모두 다섯 번 시도하고 그 뒤로는 시도하지 않는다. `doctor`의 `P1 알림` 줄과 problems에 미전달로 나온다. 수집 틱 자체는 실패로 처리하지 않는다 |

`collect`의 보고와 `doctor`의 `P1 알림 오늘` 줄에 전달, 묶음, 미발송 건수가 나온다. `kairos notify off`는 P1 알림만 끈다. P0와 상태 경고는 끌 수 없다.

알림 표시의 이유는 `items.p1_notice`가 구분한다. 스키마 마이그레이션에서는 다음과 같이 처리한다.

- v6 이전 DB: 그 시점에 이미 있던 P1에 표시를 채운다. 그래서 기능을 배포하는 순간에는 알림이 울리지 않는다.
- v7 이전 DB: 대기 중이던 건을 보류 상태로 이어받는다.
- `doctor`의 보류 건수는 대기 중인 정상 상태이므로 문제로 표시하지 않는다.

### 알림 헬퍼

알림은 헬퍼 `ops/notifier/KairosNotifier.app`으로만 보낸다. osascript는 쓰지 않는다. osascript 알림은 '스크립트 편집기' 이름으로 뜨고, 누르면 Script Editor가 열리기 때문이다.

- 실행 파일은 `KAIROS_NOTIFIER`가 있으면 그 값을, 없으면 설치 자료 폴더의 번들을 쓴다.
- 헬퍼에는 `post '<json>'`으로 제목, 본문, 항목 ID, 등급만 넘긴다.
- 헬퍼가 없거나, 권한이 없거나, 실패하면 보내지 못한 것으로 처리하고 다음 틱에 다시 보낸다.
- 감시자(`ops/kairos-watchdog.zsh`)도 같은 헬퍼로 `kairos 점검` 알림을 보낸다.
- 헬퍼의 권한은 `kairos setup`이나 `kairos notify setup`이 macOS 권한 창을 띄워 받는다. 터미널에서 따로 묻지 않는다. 백그라운드 틱은 권한 대화상자를 띄우지 않는다.
- 설치할 때는 `ops/notifier`에 번들만 복사한다. 소스와 `.build`는 복사하지 않고, 번들은 임시 이름으로 복사한 뒤 교체한다.
- 세션 거부 목록에는 헬퍼 실행 파일의 이름과 설치 경로가 들어 있다.

헬퍼의 종료 코드 0을 전달 성공으로 본다. 알림 권한이 꺼져 있거나 방해 금지 중이면 화면에 뜨지 않아도 전달한 것으로 기록된다. 설치한 뒤 알림이 실제로 뜨는지 한 번 확인한다.

### 알림을 눌렀을 때

헬퍼 알림을 누르면 헬퍼가 `kairos reveal <ID>...`를 호출한다.

1. reveal은 ID 1~20개를 검사하고 `reveal.json`(`{"items":[..],"at":<ms>}`, 0600)을 쓴다.
2. `orca plugin open`으로 패널을 열고 `open -b com.stablyai.orca`로 Orca를 앞으로 가져온다.
3. Orca가 꺼져 있어 패널을 열지 못했지만 앞으로 가져오기는 성공했다면, Orca가 뜰 때까지 0.5초 간격으로 8초 동안 패널 열기를 다시 시도한다.

Orca 단계가 실패해도 reveal은 성공으로 응답한다. `next --json`은 최근 10분 안에 쓴 `reveal.json`만 `reveal` 필드로 싣는다. 형식 번호는 바뀌지 않는다.

## triage

`kairos triage`는 기준선 객체(담당 이슈, 내 PR, 리뷰 요청)를 10건씩, 항목 ID가 있는 대기 행으로 만든다. 유지하기로 한 항목은 목록에만 남아 있다가 사람의 새 이벤트나 배포 연결이 생기면 다시 올라온다.
